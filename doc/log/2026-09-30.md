# 2026-09-30

## Android app: the first phone run (0114 follow up)

Tags: #android #bug #decision

- Symptom: the game APK (0114, version code 208) loaded on the phone, read the asset list and the first file, then logged `error: cannot copy data/bindings.sjson from the app: Permission_Denied`. The logcat showed an SELinux denial right before it: `avc: denied { read } for name="/" ... tclass=dir`.
- Cause: `os.make_directory_all` opens `/` with `O_DIRECTORY` to walk an absolute path component by component (`core/os/path_linux.odin`), and Android's policy refuses an untrusted app that read. A plain `mkdir` below the app's own folder is allowed.
- Decision: `make_directories_below` (`data_load.odin`) makes each directory of the asset's relative path under the app folder with `os.make_directory`, tolerating existing ones. No general replacement of `make_directory_all` elsewhere: the desktop builds keep it.
- Also in that logcat: `libsigchain: Setting SIGSEGV to SIG_DFL` from `install_crash_handlers`. bionic's `struct sigaction` on 64 bit puts `sa_flags` first and the handler second, `core:sys/posix` follows glibc (handler first), so bionic read the handler field as SIG_DFL and the flags from the handler pointer. Decision: the handlers are not installed on Android (`when ODIN_PLATFORM_SUBTARGET != .Android`), since the back trace is a stub there (0114) and Android's crash reporter writes the native trace to logcat.
