- Fixed point for every accumulating simulation quantity, floats only in rendering and input, per tick state hash in debug builds with a two run determinism test.

## Couch test 1 findings

- Couch test 1 ran on the play build of e218d63. The game crashed while mining hematite under a lake: a bounds check on a mesh worker, where a water block on a chunk's top layer under different water in the chunk above read one cell past the border shell. Fixed in `0479d6a`, with the regression test reproducing the exact index. Autosave worked as designed (five simulated minutes) and the reload picked the save up.
- The session log showed the gamepad without gyro and accelerometer. The running game's environment carried Steam's ignore list with the controller's ids and Steam's virtual gamepad info file, and the kernel showed Steam's virtual "Microsoft X-Box 360 pad 0": Steam Input was on for the shortcut, so SDL saw the virtual pad relabelled as "Steam Controller" 28de:1302, without pads or sensors. The tells are recorded in `doc/input.md`.
- Work item 0043 (developer mode) is written from the couch test: a Developer entry in the pause menu usable on the gamepad, `--chapter` and `--give`, runtime error text in the log, the autosave interval on the settings screen.

## Gyro drift

- Couch report: with a thumb on the right stick the view drifted at a speed set by the gyro sensitivity, the gyro toggle stopped it, and turning the controller did nothing. The game applied a constant reported rate as rotation. Fix: a gyro bias learned at rest while not aiming, subtracted with a deadzone, and readings past the full scale treated as misreads. Whether the sensor data itself is right over Bluetooth beside Steam's layer is still open; the diagnostics now show raw, bias and corrected values for the next test.

- Working rule: when the user indicates a task, subagents start without a second confirmation.

## Gyro under Steam's layer

- SDL's Triton driver and Steam both set the controller's IMU mode with no arbitration and SDL parses the layout it asked for, which explains the constant rotation the couch saw and why the gyro did not respond. With Steam's layer present the game now ignores SDL's gyro and takes it from Steam's layout as mouse movement, as the user's other games do; the bias calibration stays as a guard when SDL's gyro is the source (desktop mode, no Steam Input).
