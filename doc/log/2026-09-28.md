# 2026-09-28 Tree species and felling

Tags: #generation #trees #felling #save #decision

## Work item 0059 implemented

- Six tree species in the new content file `data/trees.sjson` (oak, birch, pine, acacia, palm, dead tree), picked per tree by weight from each biome's `trees` list; a biome with trees and no list is refused. Crowns are round, conical, flat or none, trunks 4 to 16, roots on tall oaks and pines. Forest and plains get clearings from a new appended `Clearings` sub seed (wavelength 48), plains a higher density so its trees stand in groves.
- `LEAF_REACH` is 4 and `FEATURE_MAXIMUM_HEIGHT` 20, from the species limits (`MAXIMUM_CROWN_RADIUS`, `MAXIMUM_TRUNK_HEIGHT`) the trees file is validated against. `GENERATOR_VERSION` is 4, so saves from 0058 show "terrain changed".
- Felling: mining a log drops the logs above it as loose items; the leaves around the column are queued and decay after 1 to 4 seconds unless a log lies within 4 blocks (Manhattan). The queue is the second later table of `entities.bin`.
- Decision: a conical crown over roots starts at least 6 blocks above the root, not at a third of the trunk, so no needle lies within the support distance of a root and a felled pine leaves no crown hanging on its roots.
- Decision: trees keep 4 blocks off the landing pad, since the pad clears only 10 blocks above itself and trees now grow to 20.
- Decision: the sapling item is named in `data/trees.sjson` (`sapling_item`) and checked against the items at load, rather than named in code.
- Decision: the simulation reads the tree blocks from the session's generator (`simulation_tree_felling`), so `tick_world` takes them as a parameter (empty in tests without trees) and `src/loop.odin` passes them.

## Work item 0060 implemented: block textures and item icons

Tags: #rendering #textures #icons #ui #hot-reload #decision

- Block tiles come from `data/textures/blocks/<id>.png` with `_top`, `_side` and `_bottom` overrides, decoded with `core:image/png` (no raylib, so tests read the committed files); a missing, undecodable or wrongly sized file falls back to the colour tile, the last two with a log line. The atlas layout and the mesher are unchanged.
- Item icons: an item atlas with a tile per item (tile index = `Item_Id`), `Item_Icon_Kind.Item_Tile` and an `Item_Tile` draw command. `Item_Tile` is appended to both enums so a zeroed `Item_Icon` is still `Block_Tile` as before.
- Decision: `item_icon` keeps its signature, so the registry learns which items have a tile through `Item_Registry.icon_loaded`, a slice owned by the item atlas and reassigned whenever the atlas is rebuilt (start, content reload, texture change). Callers outside the icon code need no change.
- Decision: the item atlas reuses `Atlas_Layout` (`item_atlas_layout_for_item_count`) instead of a separate layout type, so the origin and size helpers serve both atlases.
- Decision: belt and loose item icons are drawn without depth writes, flushed around the batch: raylib's default shader does not discard transparent texels, so with depth writes a quad's clear corners would hide whatever is drawn behind them later. An icon may then show over an item drawn later behind it; acceptable at 0.4 blocks.
- Decision: an item's average colour counts texels with alpha 128 and up; it is kept with the atlas for the map, which does not use it yet.
- Items held by machines (`render_entities.odin`) stay cubes; that file was outside the item's scope.
- The Textures category's toast needed a new string, `reload_textures_done`, in `data/strings/en.sjson`.
