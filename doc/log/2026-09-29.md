# 2026-09-29 Shaders that survive Gladio

Tags: #windows #shaders #gladio #decision

## Work item 0105 implemented

- Symptom: on the user's phone (Winlator, Mali GPU) the window opens and the game dies loading the chunk shader with "SHADER: [ID 12] Link error: Link failed because of missing fragment shader." and no compile log. The `gl:` line (0104) reads `vendor ARM, renderer Gladio, version 3.3, glsl 3.30`.
- Gladio is Winlator's OpenGL wrapper over the phone's GLES driver (`brunodev85/winlator-app`, `app/src/main/cpp/gladiorenderer/src/shader_converter.c`). It answers `GL_COMPILE_STATUS` with success while the compile is pending, rewrites the GLSL line by line into GLSL ES 3.20 and compiles it at link time; its compile error goes to the phone's logcat, never to the program, which is why only the link fails.
- The rewriting rule: `implicitConvertIntToFloat` runs on every line with an operator. When any word of the line is a registered variable of a float type (`float`, `vec2`, `vec3`, `vec4`, `const` globals included), every bare integer literal on the line gets `.0` appended and every `int` or `ivec` variable is wrapped in `float()` or `vecN()`. `uint` and `uvec3` are not in its type table, and a literal with a `u` suffix is not an integer to its `is_int`, so both pass untouched.
- The line that broke, in both fragment shaders: `return 1.0 + brightness_jitter * (float((hash >> 8) & 255u) / 127.5 - 1.0);`. `brightness_jitter` is a `const float`, so `hash >> 8` became `hash >> 8.0`. The other shifts shared their lines with no float variable and survived by luck; the vertex shaders have no integer literals.
- Decision: every integer literal in the shaders carries the `u` suffix, enforced by `shader_source_test.odin`, rather than working around Gladio per line. Shifting a `uint` by a `uint` literal is the same operation, so the hash is bit for bit the same and the CPU side (`texture_variation.odin`, `texture_periodicity_test.odin`) is untouched.
