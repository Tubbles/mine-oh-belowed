# 0142: Code cleanup: dead definitions, duplicates, misfiled files, comment history

Status: implemented

## Goal

The first step of the architecture cleanup (user, 2026-09-30, after the measurements in `doc/log/2026-09-30.md`, Architecture cleanup). The code is clean at the small scale (3,989 procedures, median 8 lines, 3 exact duplicate groups, 7 definitions never referenced, 18 used only by tests) and this item removes that remainder, so the audits (0143) start from a tidy tree, and adds the two scripts the audits and the code map use.

## Change

- Never referenced definitions, each checked before removal (a symbol the linker reaches through `--wrap` or `@(export)` is not dead): `refresh_belt_lines`, `destroy_fluid_registry` (a destroy that is never called is a leak or dead; decide which), `set_shader_vector3`, `skip_bytes`, `DEEP_TEST_VEIN`, `lay_save_test_oil`, and `android_wrapped_main` only if the link does not reach it.
- Definitions used only by tests (18, listed by `tools/check_dead_code.py`): for each, either the test moves to the production path and the definition goes, or the definition is a test seam worth keeping and the item says why. `queue_craft` (the UI uses `queue_crafts`), `chapter_done`, `quest_status`, `move_or_swap`, `plan_belt_run`, `fluid_network_of`, `load_chunk_now`, `light_color_level`, `region_deep_veins`, `technology_total_seconds`, `ui_radial`, `face_tile_orientation`, `deserialize_chunk`, `destroy_voxel_model`, `reset_data_edits_reading`, the three theme tables.
- Duplicate bodies: the five `find_*_definition_index` become one generic procedure; the two byproduct resolvers in `recipe.odin` become one; the two render pass starters become one.
- Misfiled files: a file whose name prefix puts it in one cluster while it belongs to another moves to its cluster's prefix (`world_setup.odin` is a screen, so `ui_world_setup.odin`; the graph script lists the other candidates as the edges that run against the layering). Renames only, with the doc pointers updated.
- Comment history: 416 work item references in code comments. A comment that narrates history ("since 0125", "was X, now Y") states the current behaviour; a plain "(0125)" pointer stays once per topic, as in the docs.
- Tools: `tools/check_dead_code.py` (the single pass scan of top level definitions never referenced or referenced only by tests, with an allow list for exported and linker-reached names, exit 1 on findings) and `tools/code_graph.py` (the cluster and file dependency graph: cluster edges with reference counts, mutual pairs, strongly connected components, the files with the fewest edges into the largest component). Both Python 3 without dependencies, run by hand, documented in `doc/build.md` beside `check_docs.py`.

## Verify

- `./build.sh check`, `./build.sh check-android`, `./build.sh test`, `python3 tools/check_docs.py`, `python3 tools/check_dead_code.py` (zero findings), `python3 tools/code_graph.py` (runs, prints the graph).
- The test count does not fall except where a test moved to the production path and says so in the item.

## Implementation notes

- `tools/check_dead_code.py` found at the start 6 unreferenced definitions (`refresh_belt_lines`, `DEEP_TEST_VEIN`, `destroy_fluid_registry`, `set_shader_vector3`, `skip_bytes`, `lay_save_test_oil`; `android_wrapped_main` is exempt through its `@(export, link_name = "__wrap_main")` attribute, which build.sh reaches with `-Wl,--wrap=main`) and 21 test only ones: the 18 of the list plus `simulation_state_hash`, `TILE_ORIENTATION_COUNT` and `ui_request_letter_jump`. It now reports 0.
- Deleted: the six unreferenced ones. `destroy_fluid_registry` is dead, not a leak: the content tables load into the content arena (`data_reload.odin`), which frees them together, and no other registry of that arena is destroyed one by one either. `lay_save_test_oil` was an oil fixture the save test never laid, so the save round trip does not cover oil machines (a coverage gap, not fixed here).
- Test only, moved to the production path and deleted: `queue_craft` (tests call `queue_crafts` with a count of 1, through a `queue_test_craft` fixture helper in `crafting_test.odin`), `plan_belt_run` (the test folds `belt_drag_step`, which the drag uses), `fluid_network_of` (a test helper over `find_fluid_segment`), `region_deep_veins` (`layer_veins(..., .Deep, ...)`), `quest_status` (the field read inline), `technology_total_seconds` (the test multiplies the two fields), `destroy_voxel_model` (`delete(model.cells)`), `deserialize_chunk` (`deserialize_chunk_blocks`), `ui_radial` with `draw_radial` (the test drives `radial_input` and `advance_radial`, which the hotbar radial and the letter wheel use; renamed `test_radial_selects_and_cancels`).
- Test only and dead in production, moved into the test files: `chapter_done` (`quest_runtime_test.odin`), `light_color_level` (`world_light_test.odin`), the three theme tables (`BOTTLENECK_PALETTE_COLORS` and `MAP_PALETTE_COLORS` to `accessibility_test.odin`, `UI_THEME_METRIC_NAMES` to `ui_theme_test.odin`).
- Deleted with its test: `move_or_swap`. No production code moves a slot onto a slot; the panels go through `apply_slot_primary`, whose swap and merge `test_primary_picks_up_drops_and_swaps` and `test_primary_merges_up_to_the_stack_size` cover. The test count falls by this one test (1290 to 1289).
- `ui_request_letter_jump` was the only writer of `Ui_State.letter_jump`, so the letter jump branch of `ui_list` never ran in the game (the letter wheel jumps through `recipe_position_for_letter` in the browsers). Removed the setter, the field, its reset, the branch and `list_index_for_letter`; `test_list_letter_jump` became `test_list_scrolls_the_focus_into_view`, which requests the focus directly and keeps the scroll check.
- Kept as test seams (allow list with reasons): `load_chunk_now`, `reset_data_edits_reading`, `simulation_state_hash` (cited in `doc/architecture.md`), `face_tile_orientation` and `TILE_ORIENTATION_COUNT` (the Odin mirror of the chunk shader's orientation choice).
- Merges: `find_definition_index` (generic over `[]$T`, in `data_load.odin`) replaces the item, machine, recipe, technology and block versions; `resolve_byproducts` (generic) replaces `resolve_recipe_byproducts` and `resolve_fluid_byproducts`; `begin_translucent_pass` and `end_translucent_pass` (`render_chunks.odin`) replace the water and life pairs.
- Renames: `world_setup.odin` to `ui_world_setup.odin`, `recipe_browser.odin` to `ui_recipe_browser.odin`, `technology_browser.odin` to `ui_technology_browser.odin`, each with its test file; the browsers are the pure part of their screens and only UI files reference them. Candidates left alone: `data_browser.odin` (its `ui_` name is taken by the drawing file), `save_list.odin` (a loader), `quick_transfer.odin` and `inventory_interaction.odin` (panel interaction on simulation slots). Only `doc/work/0143-architecture-audit.md` named a renamed file outside the history.
- Both scripts parse the declarations inside file level `when` and `foreign` blocks, and neither counts a definition line of a name (a platform variant in a sibling file) as a reference to it; that surfaced no new finding. `tools/code_graph.py` maps `render` to `presentation`, `haptics` and `system` to `ui`, `item.odin` to `content` by a file override, and assigns `hot_reload`, `benchmark_factory`, `diagnostics` and `developer` by their edges. Largest strongly connected component: 185 of 193 files; outside it (8) `export_access_desktop.odin`, `jni_indices.odin`, `local_zone.odin`, `local_zone_posix.odin`, `local_zone_windows.odin`, `main_android.odin`, `render_frustum.odin`, `run_length.odin`, each a component of its own.
- Comments: the item's grep (`[0-9]{4}` on lines with `//`) counts 825 lines at HEAD and 815 after; comment lines holding a work item number 740 and 730. The 416 of the measurement was not reproducible with these greps. 25 comment edits rewrote history ("since 0134", "before 0123", "carried over from 0035", "review of 0131") into current behaviour or a plain pointer, and dropped the three repeated pointers in one block. Kept on purpose: the generator version table (`generation_terrain.odin`), the old save handling (`save_remap.odin`, `save_state.odin`, `configuration.odin`), and test fixtures that stand for an old layout (`crafting_test.odin`, `touch_overlay_test.odin`).
