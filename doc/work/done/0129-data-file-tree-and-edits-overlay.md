# 0129: Data file tree and the data edits overlay

Status: implemented

## Goal

Asked on 2026-09-30: a fallback for changing any game data file from the Developer menu, on the couch and on the phone, without touching the checked in files: "a file browser showing the file structure, opening, viewing, editing (saving goes to a transparent overlay file so we can handle that case by case outside the game)", and "make the browsing a hierarchical tree so its easy to navigate". This item is the overlay and the browser (viewing); 0130 adds editing and saving; 0131 the export.

## Change

- The data edits overlay: `<state>/mine-oh-belowed/data_edits/<relative path>` mirrors the data directory (`data_edits/blocks.sjson`, `data_edits/quests/chapter_01.sjson`), beside `texture_edits.sjson`, which keeps its own format. A helper (`data_edits_directory`, like `texture_edits_path` in `loop.odin`) resolves it from `platform_directories`. `read_data_file(data_directory, relative_path, allocator)` reads the overlay copy when one exists, else the data file, and says in the log which when the overlay was taken (once per read; nothing reads per frame). Every loader of an SJSON file and the shader loader (`render_chunks.odin`) read through it: game.sjson, blocks, items, fluids, machines, recipes, technologies, contracts, notes, biomes, trees, veins, touch_overlay, bindings, developer kits, strings, the quest chapters (the chapter list still comes from the data directory's listing), sounds.sjson, fonts.sjson, theme.sjson, textures/procedural.sjson. Binary files (png, wav, vox, ttf) and the blueprints stay as they are: the browser never edits them. A broken overlay file is reported like a broken data file, naming the overlay path.
- The overlay is not under the data watcher. `apply_data_edit_change(state, relative_path)` in `hot_reload.odin` does what the watcher would: the category from `data_file_category`; a presentation category reloads in place through `apply_presentation_changes`; Content sets `reload_requested`; Restart toasts `reload_restart_needed`. 0130's save and this item's Discard call it.
- The Data files screen (`ui_data_browser.odin`, screen `Data_Files`), opened from a Data files button on the Developer screen's editors row: a hierarchical tree of the data directory, built once at open from `os.read_all_directory_by_path` recursively (directories first, then files, each sorted by name, hidden names skipped), rebuilt after a discard. Directories are rows with a chevron that Confirm expands or collapses, files are rows with their size, indented by depth; a file with an overlay copy carries an "edited" tag. Only the visible rows are declared, so focus navigation walks the tree in order; the panel scrolls like the Developer screen; the pointer works. Confirm on a text file (`.sjson`, `.vs`, `.fs`, `.txt`) opens it in place of the tree: an SJSON file parsed with `json.parse` (`.SJSON`, `parse_integers = true`) into a second hierarchical tree, objects and arrays expandable, leaves as `key = value` (an array element by its index); other text files line by line. Both view only in this item. A binary file cannot be opened. Back returns from the file to the tree, then closes the screen. A Discard edit button, enabled while the selected file has an overlay copy, deletes the copy and calls `apply_data_edit_change`.
- The tree and the value tree are pure data with tests: the rows from a list of relative paths, the visible rows from the expansion flags, the value rows from a `json.Value`.
- Docs: `doc/ui.md` (the Developer screen's editors row, the Data files screen), `doc/architecture.md` (the state directory's `data_edits/`, `read_data_file` in the data section), `doc/build.md` (the phone's state folder), `DESIGN.md` Editors (one sentence: the data file browser is the fallback editor for everything without one of its own).

## Verify

- `./build.sh check`, `./build.sh check-android`, `./build.sh test`. Tests: `read_data_file` takes the overlay copy when present and the data file otherwise (temporary directories); a data edit of blocks.sjson reports Content, of strings/en.sjson Strings; the tree from `{"a/b.sjson", "a/c.png", "d.sjson"}` lists `a` (collapsed) before `d.sjson` and shows `b.sjson` before `c.png` once expanded; the value rows of `{x = 1, y = [1, 2]}` show `x = 1`, `y` expandable, then `0 = 1`, `1 = 2`; the UI audit covers the screen with the tree and with a file open.

## Implementation notes

- `read_data_file` returns `(data, path, error)`: the path is the file actually read, so a broken overlay copy is named in the loader's own problem line. `read_logged_data_file` is the log and give up variant most content loaders use; it replaces the old `read_data_file(data_directory, file_name)` in `generation.odin`.
- Under `odin test` the overlay directory is "" so the suite never reads a machine's overlay; `read_data_file_with_edits` is the testable form.
- `apply_data_edit_change` returns the category, which the test checks. The Strings case runs the real strings reload, which fails in the test (no data directory) and toasts.
- Object keys in the value tree are sorted by name, since `json.Object` is a map and the file's order is lost.
- The chevrons are `>` and `v` (glyph coverage, see the log). The selection follows Confirm or a tap, not the focus, so a passing mouse does not move it; Discard edit works on the selected (last opened) file. A binary file toasts "Only text files open here".
- Back and Pause (and the touch row's Back and a tap off the panel) close an open file before they close the screen; the panel also has its own Back button.
- `ui_pointer_test.odin` got the screen in its every screen touch Back list.
- Review fixes: the overlay log line comes once per read, not once per file per load (the strings and `textures/procedural.sjson` are read by two loaders at start); nothing reads per frame. Closing an open file (Back, B, Pause, the touch row's Back, a tap off the panel, the panel's Back) only sets `close_requested`; `serve_data_browser` frees the file between frames, because the Back frame's draw list points into the file's arena (freeing it during the UI pass crashed the game). Rows outside the scroll region are declared for the focus but not drawn. The problem line reads error first, then the path, wrapped. The heading of a file shown from the overlay carries the edited tag. `read_strings_file` returns the path it read, so a broken overlay copy of the strings is named in the reload's problem.
