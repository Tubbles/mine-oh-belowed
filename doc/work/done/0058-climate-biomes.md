# 0058 Biomes from climate

Status: implemented
Milestone: M11

## Goal

Six biomes chosen by independent noise. A temperature and moisture map chooses biomes so transitions read as a landscape, and new biomes give the planet variety.

## Deliverables

- Temperature (latitude band plus noise) and moisture maps choose the biome per column; the existing six keep their names and gain climate ranges in `data/biomes.sjson`.
- New biomes in data: wetland, steppe, highland, cold barrens with snow blocks, badlands with exposed rock layers, coastal dunes; each with ground blocks, ground cover (grass tufts, flowers, dead wood as decoration blocks), tree species, boulder style and a vein type bias.
- The map screen colours by biome; the HUD compass names the biome under the player.
- Tests: climate to biome mapping, every biome reachable for the test seeds, spawn still found.

## Verify

- Builds and tests pass.
- User: Walk a transition; screenshots.

## Notes

Scope decisions (main agent, 2026-09-27): ground cover decoration blocks (grass tufts, flowers, dead wood) need blocks that are not cubes and move to 0061; tree species per biome move to 0059, which already owns species. This item delivers the climate, the biome table, the new biomes with cube blocks, the vein bias, the map colours and a biome name in the HUD.

Implementation pointers, decisions taken so the item is unambiguous:

- Climate, in `src/generation_terrain.odin` next to `terrain_moisture`: `terrain_temperature(seeds, x, z, height)` in -1 (cold) to 1 (hot) is a latitude band along z plus noise minus an altitude lapse: `cos` of z over `TEMPERATURE_PERIOD` (6000 blocks) with the phase chosen so the origin is temperate (about 0.1) and it gets cold about 1500 blocks one way and hot the other way, plus a `Temperature` purpose noise (new `Generation_Purpose`, appended) at wavelength 600 and amplitude 0.35, minus 0.006 per block above sea level. Moisture stays as it is. `Column_Sample` gains the temperature; `select_biome` takes it.
- Biome table (`src/generation_biome.odin`, `data/biomes.sjson`): `Biome_Definition` gains `minimum_temperature` and `maximum_temperature` (a definition without them accepts every temperature, so the current entries keep working until they get ranges), `map_color` (`[3]u8`, for the map), and optional `layer_block` with `layer_thickness` for a filler that alternates between `filler_block` and `layer_block` every `layer_thickness` blocks of absolute height (`terrain_block` does the alternation; badlands). Validation: a temperature minimum above its maximum and a layer thickness below 1 are errors. Selection stays "first entry whose ranges contain the column", so the order in the file is the rule.
- New biomes, in this order in the file after lake and mountains and before the existing lowland ones: `cold_barrens` (temperature up to -0.45, height 0 and up, top `snow`, filler `frozen_dirt`, no trees, boulders 0.2), `highland` (height 24 to 47, moisture 0 and up, top `grass`, filler `stone`, trees 0.02, boulders 0.3; `hills` keeps the drier side of that range), `badlands` (temperature 0.3 and up, moisture up to -0.2, height 6 to 47, top `red_rock`, filler `red_rock` layered with `pale_rock` every 4 blocks, no trees, boulders 0.2), `steppe` (temperature 0.2 and up, moisture -0.35 to 0.1, height 0 to 23, top `dry_grass`, filler `dirt`, trees 0.005, boulders 0.05), `wetland` (moisture 0.6 and up, temperature -0.2 and up, height 0 to 3, top `mud`, filler `dirt`, trees 0.03, no pits: a water pit would need the flow rules checked, left for later), `coastal_dunes` (height 1 to 3, temperature -0.2 and up, moisture up to 0.3, top and filler `sand`, no trees). The existing six get temperature ranges that keep them where the climate is temperate (plains, forest, hills) or warm (desert, tar flats). Every biome gets a `map_color`.
- New blocks in `data/blocks.sjson` as colour textures like the rest (textures are colours until 0060): `snow`, `frozen_dirt`, `dry_grass`, `mud`, `red_rock`, `pale_rock`, each solid, minable with the dirt or stone hardness, with a `name_key` and strings. Drops follow the existing pattern (read how `grass` and `tar` map to items in `data/items.sjson` and `block_drop_stacks`): `frozen_dirt` and `dry_grass` drop the dirt item, `red_rock` and `pale_rock` drop stone, `snow` and `mud` get their own items that place their block. Discovery flags as the neighbours have them.
- Vein bias: `data/veins.sjson` already restricts a type by biome id lists (`biomes`); extend them for the new biomes so each new biome has at least one restricted type (for example coal in steppe and wetland, lead in highland, zinc and nickel in badlands, nickel in cold barrens) and check `resolve_biome_names` still resolves. Types with an empty list stay everywhere.
- Spawn (`src/generation_spawn.odin`): the pad's column must be temperate, temperature between -0.2 and 0.5, checked first since it is the cheapest; the origin is temperate by construction so the ring search stays fast. Update the "Spawn requirements" paragraph in `doc/quests.md`.
- Map (`src/ui_map.odin`): the surface layer blends each pixel's block colour with the biome's `map_color` at half strength before the height shading, and the legend lists the biomes present in the image with their colours and marks the player's biome. The biome per pixel comes from `sample_column` on the session's generator (pure, about 65 thousand samples for the full image), computed only when the painted frame changes (centre or zoom) and kept in a parallel array in `Map_View`, never on the half second repaint. `Screen_Context` (`src/ui_screens.odin`) gains `generator: ^Generator` (nil without a world), set in `make_screen_context` (`src/loop.odin`) from the session.
- HUD (`src/hud.odin`): there is no compass strip (`doc/ui.md` claims one at top centre; correct that sentence). Instead a biome banner: when the biome under the player has changed and stayed changed for `BIOME_BANNER_DEBOUNCE_SECONDS` (2), the biome's name fades in at top centre below the brownout warning's spot for `BIOME_BANNER_SECONDS` (3) and fades out. The debounce and the banner timing are a pure state machine over the frame time (rendering state, not simulation), tested without raylib.
- Tests: `terrain_temperature` is temperate at the origin and colder about 1500 blocks away, and colder on a mountain than at sea level below it; every biome id appears at least once on each test seed over a coarse sample of 4096 by 4096 blocks with stride 32; the badlands filler alternates as configured; the biome file validation rejects a bad temperature range and a zero layer thickness; the spawn is found for the seven seeds and its pad column is temperate; the map colour blend is pure and tested; the banner state machine debounces and times out; the existing generation and streaming tests keep passing (the generation time budget from 0057 holds, report the ms per chunk).
