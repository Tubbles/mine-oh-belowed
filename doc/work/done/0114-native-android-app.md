# 0114 The game as a native Android app

Status: implemented
Milestone: M11

## Goal

The user's phone ran the Windows build through Winlator (0102 to 0109); the spitball of 2026-09-29 chose a native Android app instead, with its own touch overlay later (0115). This item is the app itself: `./build.sh android` and a CI job produce a signed APK of the game, it starts on the phone with the build stamp on the title screen, a tap on the title screen starts a world that renders with the shaders, and the log is a file the user can fetch. Movement on the phone waits for the overlay; a Bluetooth or USB gamepad works through raylib at once. The toolchain, the Android raylib archive, the binding's Android import branch, the keystore and a working hello world are 0113 (read its Implemented section first: the exact build and bundle commands and the manifest).

Facts checked on this machine:

- Odin build tags know the subtarget: `#+build linux:android` includes a file only for the Android subtarget and `#+build !linux:android` excludes it there (probed with the dev-2026-09 compiler on the host, `tmp/odin-src/parser.cpp` around line 7050).
- Odin links a foreign library only when one of its procedures is used: a package importing `vendor:sdl3` without calling it gets no `-lSDL3` on the link line (probed with `-show-system-calls`). Types and enums of the import cost nothing. In the game only `src/input_sdl3.odin` calls SDL (`grep -l 'sdl\.' src/*.odin`); `src/bindings.odin` uses `sdl.GamepadButton` and `sdl.GamepadAxis` as types and stays as it is.
- Entry point (0113, verified there): Odin dev-2026-09 refuses the executable build mode for the Android subtarget (only `shared`, `object`, `assembly` and `llvm-ir`), and in `-build-mode:shared` the runtime exports a C `main` that returns 0 at once and registers no INIT entry. So the Android build is `-build-mode:shared -no-entry-point -extra-linker-flags:-Wl,--wrap=main`, and a `#+build linux:android` file exports `__wrap_main :: proc "c" (argc: i32, argv: [^]cstring) -> i32`, which raylib's `android_main` reaches through the wrap: it sets `runtime.args__ = argv[:argc]`, sets `context = runtime.default_context()`, calls `runtime._startup_runtime()`, then the game's `main()`, then `runtime._cleanup_runtime()`, and returns 0. `odin bundle android` hands aapt `<dir>/lib` as a directory argument, so the library must sit at `<dir>/lib/lib/arm64-v8a/libmain.so` to land at `lib/arm64-v8a/libmain.so` in the APK.
- raylib's Android platform (`tmp/raylib-src/src/platforms/rcore_android.c`): `android_main` sets its app pointer and calls the C `main(1, {"raylib", NULL})`, so `os.args[1:]` is empty and, since `core:os` finds the environment at `argv[argc]` (that NULL), every environment variable reads as unset on Android; `os.get_env` and `os.lookup_env` are safe to call and return nothing. `GetAndroidApp()` returns the `android_app` whose `activity` (`ANativeActivity`, `<ndk sysroot>/usr/include/android/native_activity.h`) holds `internalDataPath`, `externalDataPath` and `assetManager`; the binding does not declare it. raylib wraps `fopen` through `__wrap_fopen`: a read of a relative name looks in the APK assets first, then under `internalDataPath`, so `rl.LoadFileData("data/strings/en.sjson")` reads the asset; Odin's `core:os` reads the real file system only. Correction after the 0113 phone test: the wrap is not inside the archive. `rcore_android.c` (its comment around line 280) says the final link must pass `-Wl,--wrap=fopen`, a static archive cannot carry it; without it `__real_fopen` stays undefined, a shared library links anyway, and the hello APK failed at `dlopen` with "cannot locate symbol __real_fopen referenced by libmain.so". The Android link therefore passes `-Wl,--wrap=fopen` and `-Wl,--no-undefined`, the second so any other unresolved symbol fails the link instead of the start. Touch: the first touch sets `IsMouseButtonDown(.LEFT)` (rcore.c "Touches are considered like mouse buttons"), but `GetMousePosition` is not the touch position; `GetTouchPosition(0)` and `GetTouchPointCount()` are. `TraceLog` goes to logcat on its own. Pausing keeps the EGL context and rebinds the surface on resume (`contextRebindRequired`).
- The shaders under `data/shaders/` start with `#version 330` and use `uint` arithmetic, `texture`, `out` variables and `flat`; GLSL ES 3.00 has all of that once the version line says `#version 300 es` and the fragment stage declares default precisions (`precision highp float;` and `precision highp int;`, the second so the hash multiplications are 32 bit). rlgl built with `GRAPHICS_API_OPENGL_ES3` (0113) uses `#version 300 es` for its own shaders and binds the usual raylib attribute names.
- Odin's `core:sys/posix` is `#+build linux, darwin, ...`, so `logging_posix.odin`, `command_socket_posix.odin` and `local_zone_posix.odin` compile for Android; `timezone.region_load("local")` finds no tz database there and the title screen's dates fall back to UTC (a later item may read `persist.sys.timezone`).
- `build.sh` says `bin/` is reserved for the installed play build, so the Android output goes under `build/android/`.

## Change

- Entry point: `src/main_android.odin` (`#+build linux:android`) holds the exported `__wrap_main` described above, calling the game's `main :: proc()` (which stays the desktop entry point) between the runtime start and cleanup. Nothing else in `src/` needs to know.
- SDL stays off Android: `src/input_sdl3.odin` and `src/input_sdl3_test.odin` get `#+build !linux:android` as their first line. A new `src/input_sdl3_android.odin` (`#+build linux:android`) holds what the rest of the game calls from that file (grep the callers: `main.odin`, `loop.odin`, `diagnostics.odin`, others): `Sdl3_Input_State :: struct {}`, `init_sdl3_input` returning `false, "no SDL on Android"` so `start_input_backend` takes the raylib backend and logs why, `read_sdl3_input_frame` returning `previous`, `apply_sdl3_haptics` and `shutdown_sdl3_input` doing nothing, the label procedures returning `""`, and anything else the compiler asks for, each a one liner. `test_static_runtime_imports_stay_out_of_windows` and the flake's `substituteInPlace` lines are untouched.
- `src/platform_android.odin` (`#+build linux:android`): the foreign declarations Android needs, `GetAndroidApp` from `shared:raylib`'s archive is not in the binding, so declare `GetAndroidApp :: proc() -> ^Android_App ---` against `shared/raylib/android/libraylib.a` (the binding's Android `foreign import` in `platform.odin` from 0113 can carry it; put it there if that reads better), with `Android_App` (the leading fields of `android_app` from `<ndk>/sources/android/native_app_glue/android_native_app_glue.h`: `user_data`, `on_app_cmd`, `on_input_event` as `rawptr`, then `activity: ^Android_Native_Activity`) and `Android_Native_Activity` (`callbacks`, `vm`, `env`, `clazz` as `rawptr`, `internal_data_path`, `external_data_path` as `cstring`, `sdk_version: i32`, `instance`, `asset_manager` as `rawptr`, `obb_path: cstring`), both checked against the NDK headers; `__android_log_write :: proc(priority: i32, tag, text: cstring) -> i32 ---` from `system:log`; `glGetString :: proc(name: u32) -> cstring ---` from `system:GLESv3`. Plus `android_data_paths() -> (internal, external: string)` reading the activity.
- Directories (`platform_paths.odin`): on Android `platform_directories` returns `android_platform_directories(internal, external)`, pure and tested on any host: base is `external` when not empty (the `Android/data/<package>/files` folder, reachable over USB and by file managers with access to it) else `internal`; `config_home = base/config`, `data_home = base/share`, `state_home = base/state`, no runtime directory, no home. The helpers append `mine-oh-belowed` as they do, so the log lands at `<base>/state/mine-oh-belowed/log.txt`, the saves at `<base>/share/mine-oh-belowed/saves/`, the configuration under `<base>/config/mine-oh-belowed/`. `platform_log_directory` needs no Android case since `state_home` is absolute. The problem-line constants (`CONFIG_HOME_VARIABLES` and friends) get Android wording.
- Data (`data_load.odin`): on Android `resolve_data_directory` returns `<internal>/data` after `sync_android_assets(internal, build_info)`: the bundle carries `assets/data_files.txt`, one path per line relative to the repository (`data/strings/en.sjson`), written by `build.sh`; each file is read with `rl.LoadFileData` (the asset) and written under `<internal>/` with `os.make_directory_all` and `os.write_entire_file`, then `<internal>/data/.build_stamp` receives the build info string, and a later start whose stamp matches skips the copy. A read or write failure logs `error: cannot copy <file> from the app: ...` and the start fails like a missing data directory does today. The copy runs before the window opens; the asset manager is ready from `main` on (raylib set its app pointer before calling `main`).
- Shaders (`render_chunks.odin`): `load_shader_pair` reads both files with `os.read_entire_file` and loads through `rl.LoadShaderFromMemory` on every platform, so there is one path; on Android the source first goes through the pure `shader_source_for_gles(source) -> string`: the first line `#version 330` (any trailing profile word) becomes `#version 300 es` followed by `precision highp float;` and `precision highp int;` lines, the rest is unchanged, and a source without a version line is returned as is. Tests in `shader_source_test.odin`: the rewrite of a two line source, the untouched remainder, the version-less source, and that the shipped shaders all begin with a version line. The retry (0109) stays.
- Display (`display.odin`, `loop.odin`): `Window_Platform` gains `Android`; `current_window_platform` returns it there, `cursor_window_size` returns `GetScreenWidth` and `GetScreenHeight`, `display_is_desktop_scaled` is false, `log_gl_info` uses the `glGetString` declared above instead of `glfwGetProcAddress`, `run_game` opens the window with `rl.InitWindow(0, 0, ...)` (raylib sizes it to the screen) and the display mode changes (borderless, fullscreen, resolution) do nothing on Android while vsync and the frame cap still apply. Every GLFW call sits under `when ODIN_PLATFORM_SUBTARGET != .Android`; the 0113 binding makes a stray one a compile error.
- Logging (`logging.odin`): on Android every line `log_printf` writes also goes to logcat through `__android_log_write` with priority 4 (info) and tag `mine-oh-belowed`, so `adb logcat -s mine-oh-belowed raylib` shows a start; the file stays the user's copy.
- Touch as the pointer: where the UI takes the pointer position from `rl.GetMousePosition` (find it: `ui_input.odin`, `input_raylib.odin`), on Android it takes `rl.GetTouchPosition(0)` while `rl.GetTouchPointCount() > 0` and keeps the last position otherwise, and whatever makes the pointer visible after mouse movement treats a touch the same, so the title screen, the menus and the settings can be tapped. Nothing else of the overlay yet.
- The manifest `tools/android/AndroidManifest.xml` (start from the hello world's in 0113's Implemented section): package `io.github.tubbles.mineohbelowed` (the GitHub account and the repository name), `android:versionCode="@VERSION_CODE@"` and `android:versionName="@VERSION_NAME@"` that `build.sh` fills (the commit count `git rev-list --count HEAD`, so each newer build installs over the last, and the build stamp), `uses-sdk` 28 to 34, `uses-feature android:glEsVersion="0x00030000"`, `application` with `android:label="@string/app_name"` from `tools/android/res/values/strings.xml` copied into the bundle's `res/` (0113 found that a literal label does not reach the badging), `android:hasCode="false"`, `android:isGame="true"`, one `android.app.NativeActivity` with `android:theme="@android:style/Theme.NoTitleBar.Fullscreen"`, `android:screenOrientation="landscape"`, `android:configChanges="orientation|keyboardHidden|screenSize|screenLayout"`, `android:exported="true"`, the `meta-data` `android.app.lib_name` = `main` and the MAIN and LAUNCHER intent filter. No icon yet (a later item).

Deviations from the plan, accepted:

- The link flags: `-Wl,--no-undefined -Wl,--wrap=main -Wl,--wrap=fopen` (the correction above), plus `-Wl,--wrap=` for six glibc functions Odin's core library links on Linux that Android 9's bionic lacks, which `--no-undefined` reported: `__errno_location` (`core:c/libc`), `pthread_setcancelstate` and `pthread_setcanceltype` (`core:thread`), `backtrace`, `backtrace_symbols` (`core:debug/trace`) and `backtrace_symbols_fd` (`logging_posix.odin`). The leaf package `src/android_libc/`, imported with `@(require)` from `platform_android.odin`, exports each as `__wrap_<name>` (`__errno_location` calls bionic's `__errno`, the cancellation calls do nothing and succeed, the back trace calls return no frames). Exports under the plain names were tried first: `__errno_location` was never emitted and `backtrace_symbols_fd` was emitted in one build and not in the next, since each name is also a foreign declaration elsewhere in the program; `-Wl,--defsym=__errno_location=__errno` failed ("symbol not found: __errno"). None of them is provided at run time by something we do not link, so `--no-undefined` stays. The one undefined symbol left is `memfd_create`, a weak reference from the NDK's `libclang_rt.builtins-aarch64-android.a`, which the loader allows.
- `core:thread` and `core:sys/posix` link `system:pthread`, and the NDK has no `libpthread` ("unable to find library -lpthread"), so `build.sh` writes an empty archive `build/android/linker-shims/libpthread.a` and passes `-L` to it; the pthread functions come from libc.
- `check-android` passes neither `-minimum-os-version` (`odin check` refuses the flag: "'minimum-os-version' is supported with the following commands: run, build, test, bundle android") nor the shared build mode (the check accepts the default).
- Moved, not stubbed: `input_actions.odin` now holds the SDL-free parts of `input_sdl3.odin` that the bindings, `ui_input.odin` and the tests use on every platform (`LEFT_TOUCHPAD_INDEX`, `RIGHT_TOUCHPAD_INDEX`, `TRIGGER_PRESS_THRESHOLD`, `TOUCHPAD_LOOK_PIXELS_PER_PAD_WIDTH`, `GYRO_LOOK_PIXELS_PER_DEGREE`, `touchpad_finger`, `gyro_look_active`, `normalize_sdl_axis`, `sdl3_look_delta`, `rumble_level`), unchanged, so their tests still run on Android's check. `input_sdl3_android.odin` holds the one liners the plan names plus `right_pad_click_down` (false).
- The asset copy removes the old `<internal>/data` before copying when the stamp differs, so a file a newer build dropped does not linger. The version name is the build info (commit and build time) without the `0.0.0` of `BUILD_STAMP`, which only the Odin source knows.
- `apply_display_changes` is split into `apply_window_mode_changes` (skipped on Android) and `apply_vsync_and_frame_rate_changes`. A failed data copy on Android logs `error: no data directory: the copy from the app failed (see above)` instead of the desktop hint.
- Touch: raylib 6.0's `rcore_android.c` does set the mouse position to the first touch on each touch event (around line 1467); the pointer still reads `GetTouchPosition(0)` while a finger is down and keeps the last one after, as planned, through the pure `touch_pointer_position`. A tap sets the left button, and `update_pointer` already moves the pointer on a press, so nothing else changed for visibility.
