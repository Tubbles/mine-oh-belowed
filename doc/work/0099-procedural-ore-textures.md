# 0099 Procedural ore textures

Status: todo
Milestone: M11

## Goal

Couch report (2026-09-28): the per block variation of 0088 is good, but the ore tiles paint their blobs near the tile's edges, so a field of ore still shows a macro pattern, now a grid. The user wants textures as mathematical descriptions generated by the game from parameters in data, no painted files (not even by scripts), starting with the ores, with an in-game editor (0100) that changes each texture's parameters and seed on the fly. This item is the generator and the data, 0100 is the editor.

## Why the grid

`tools/make_placeholder_textures.py`, `ore_pattern`: the blobs are the top 20 percent of an isotropic field, white noise blurred by a Gaussian. Read how the blur treats the tile's edges. The expected cause: edge texels are blurred over fewer neighbours, keep more of the white noise's variance and cross the threshold more often, which puts the blobs at the edges. A field that wraps around the tile (a blur on the torus) has the same statistics everywhere. State the cause in the log entry once read.

## Deliverables

- A pure generator in Odin, new `src/texture_generate.odin`: `generate_ore_tile(parameters: Ore_Texture_Parameters, stone, ore: [3]u8) -> Tile_Pixels`. Periodic isotropic noise from a hash of the seed and the texel, blurred on the torus so the tile has no edge bias; the blobs are the texels above the field's quantile given by the share, in the ore colour with their own grain, over stone with its grain, with an optional rim (a darker outline around a blob) for depth. Parameters, five to eight, each an `f32` or an integer with a range and a step suited to a slider, plus the `seed`: the blob share, the blob width (the blur's width in texels), the stone grain, the ore grain, the rim strength, and whatever else the look needs. Same parameters, same pixels: no wall clock, no global state.
- Data: new `data/textures/procedural.sjson`, a list of entries `{block = "<id>", kind = "ore", seed = <int>, <parameter> = <value>, ...}`. The stone and ore colours come from `blocks.sjson` (`texture.side` of the block and of `stone`), not from this file. Strict: an unknown key, an unknown block, a value outside its range or a kind other than `ore` is an error naming the entry. Entries for the seven ores (`hematite_ore`, `coal_ore`, `chalcopyrite_ore`, `cassiterite_ore`, `galena_ore`, `sphalerite_ore`, `pentlandite_ore`) with defaults you believe in: the current PNG tiles show the intent (a blob share around 0.2, blobs one to two texels wide), and vary per ore where it helps (coal darker and coarser, galena blocky). Delete their PNG files under `data/textures/blocks/` so there is one source; the item icons stay. Take the ore family out of `tools/make_placeholder_textures.py` so a rerun does not write them back; `gold_quartz` keeps its files for now.
- Atlas: `read_block_face_tiles` (`src/render_atlas.odin`) takes the generated tile for a block with a procedural entry (all three face groups) before looking for files. The layout stays; `replace_chunk_atlas` and the hot reload rebuild it as for PNG files, and `data/textures/procedural.sjson` is a presentation file of the Textures category (`src/data_watch.odin`).
- Overrides for the editor (0100): the loader also reads `$XDG_STATE_HOME/mine-oh-belowed/texture_edits.sjson` when it exists (the same format and checks; a problem is logged and the file ignored) and its entries replace the data file's per block. The editor saves there; this item only reads it. The state directory comes from `log_directory_from_environment` (`src/logging.odin`), as the screenshots do.
- Tests: determinism; the blob count within a texel of the share times 256; every texel opaque; the wrap, a field from a single impulse has the same values one texel to each side of it across the tile's edge; the parser accepts the shipped file and refuses an unknown key, an unknown block and a value outside its range; the atlas test passes with the PNG files gone; the overrides file replaces an entry.
- Docs: `doc/content.md` (Textures: the procedural file, every parameter with its range, the overrides file), `doc/architecture.md` where the atlas line changes, `doc/log/2026-09-28.md` (the cause of the grid and the decisions), this item.
