# 0112 Double tap Jump flies, no clip is its own toggle

Status: implemented
Milestone: M11

## Goal

The developer fly mode (F6, the Developer screen, `fly on`) has no gamepad button, so on the couch, the Deck and the coming touch overlay (the native Android app series) it is a trip through the pause menu. The user (2026-09-29): "double tap jump in creative to fly should be the way dev fly mode is implemented (we have no creative mode), with normal collision checks active. And maybe tristate it with a new no clip toggle if we want to fly through the ground like it is today." Bedrock Edition is the model: a second Jump press shortly after the first toggles flight, and flight respects blocks.

## Change

- `Player` gains `no_clip: bool` beside `flying`. Flying with `no_clip` off is swept against blocks like walking; with it on the body passes through blocks as today. Walking ignores `no_clip`. Neither field is saved (`flying` is not saved today either; a loaded world starts walking).
- `fly_player` takes the world and the block registry. It keeps its velocity (`fly_camera_velocity` times the speed factor) and `on_ground = false`. With `no_clip` it adds `velocity * seconds` as today. Without it, it first calls `lift_out_of_blocks` (a body inside a block after no clip was switched off rises one block per tick, as after fly mode off), then sweeps each axis in turn (x, y, z) with `sweep_box_axis` over `player_box(player.position)`, adds the moved distance and zeroes the velocity component that was blocked, the way `move_player_horizontally` does without the step up and the sneak edge check. No water rules, no gravity.
- Double tap: `Input_Frame` gains `developer: bool`, set by `world_input` from a new `developer: bool` parameter (`loop.odin` passes `developer_mode_on(state)`), in both the blocked and the open branch, the way `apply_hold_settings` sets `sneak_toggles`. The simulation never reads the setting itself. `Player` gains `jump_tap_ticks: u8`, the ticks left of the double tap window after a Jump press, `JUMP_DOUBLE_TAP_TICKS :: 18` (300 ms at 60 Hz). A new pure `update_jump_double_tap(player: ^Player, input: Input_Frame)` runs from `tick_player` right after `apply_player_toggles` on the resolved input (so a Jump that `resolve_interact` turned into Interact does not count): every tick counts the window down; a Jump edge (`.Jump in input.just_pressed`) while the window is open and `input.developer` is set toggles `flying` exactly as `Toggle_Fly_Mode` does (velocity zeroed) and closes the window; any other Jump edge opens the window. Without `developer` a double tap does nothing, so normal play never flies by accident. The tap that toggles flight on the ground has already jumped that tick; that is fine, the toggle zeroes the velocity.
- No clip toggle: a developer `Action.Toggle_No_Clip` (keyboard F9, context world, in `data/bindings.sjson` beside F6, and in `WORLD_ACTIONS` or wherever `Toggle_Fly_Mode` is listed); `apply_player_toggles` flips `no_clip` on it. A `Developer_Action.Toggle_No_Clip` served like `Toggle_Fly_Mode`; the Developer screen's first row gets three toggles, Fly mode, No clip (`developer_no_clip = "No clip"` in `data/strings/en.sjson`), Cheat speed, with `pending_toggle` on `player.no_clip`. The command `noclip <on|off>` through `command_toggle` (a third name beside `fly` and `cheat_speed`), and `query player` prints a `no_clip` line after `flying`. The diagnostics Input page line with `flying` also prints `no clip`.
- Tests: `player_test.odin`: a Jump edge, then another within the window on a frame with `developer` set, toggles flying, and a third pair toggles it off; two edges further apart than the window do not; a pair without `developer` does not; flying with `no_clip` off forward into the stone wall of the existing wall test stops flush before it, and descending with Sneak stops on the floor (`y` stays 1); the existing `test_fly_mode_ignores_gravity_and_blocks` sets `no_clip` and keeps passing; `world_input` puts `developer` into the frame in both branches (the test near `sneak_toggles`). `developer_test.odin`: `pending_toggle` and serving `Toggle_No_Clip`. `command_test.odin`: `noclip on`, `noclip off`, `noclip maybe` (usage error), `query player` shows `no_clip`. `bindings_test.odin`: F9.
- Documentation in the same commit: the comments in `src/player.odin`; `doc/input.md` (the keyboard developer actions sentence: F6 fly mode, F9 no clip; a sentence on the double tap in developer mode and that flight collides unless no clip is on); `doc/ui.md` (the Developer screen's toggles); `doc/commands.md` (the `noclip` row, the `query player` fields); `DESIGN.md` line 36 (the flying toggle now collides, no clip is separate); a dated entry in `doc/log/2026-09-29.md` (tags `#input #developer #decision`).

## Implemented

2026-09-29: `Player` has `no_clip` and `jump_tap_ticks`; `fly_player` takes the world and the block registry and, without no clip, lifts out of blocks and then sweeps x, y and z with `sweep_box_axis`, zeroing a blocked component. `toggle_flying` is shared by `Toggle_Fly_Mode` and `update_jump_double_tap`, which runs after `apply_player_toggles` in `tick_player`: a Jump edge with the window open and `input.developer` set toggles flying and closes the window, any other Jump edge opens it for `JUMP_DOUBLE_TAP_TICKS` (18), and a tick without a Jump edge counts it down, so the second press may come up to 18 ticks after the first. `world_input` takes `developer` (`loop.odin` passes `developer_mode_on(state)`) and sets `Input_Frame.developer` in both branches. `Action.Toggle_No_Clip` (F9, in `WORLD_ACTIONS`), `Developer_Action.Toggle_No_Clip`, the Developer screen's first row with three toggles, `noclip <on|off>` (`toggle_command_state` picks the state and action per name, and the help lists it), `no_clip` in `query player` and `no clip` on the diagnostics Input page. Tests: `test_flying_without_no_clip_stops_at_blocks`, `test_double_tap_jump_toggles_flying`, `test_slow_double_tap_jump_does_not_fly`, `test_double_tap_jump_without_developer_does_not_fly`, `test_developer_mode_reaches_the_frame`, with `test_fly_mode_ignores_gravity_and_blocks` now switching no clip on, and additions to `test_developer_toggles_teleport_and_unlock`, `test_command_teleport_time_and_toggles`, `test_command_queries` and the F9 row of the bindings test. Verified here: `./build.sh check`, `./build.sh check-windows`, `./build.sh test` (1061 tests) and `./build.sh release` pass. The couch checks are the user's.
