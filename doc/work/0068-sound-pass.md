## Notes

Implementation pointers (main agent, 2026-09-28), decisions taken so the item is unambiguous. Lands after 0066 (its step detector and frame memory of the placed and mined counters are the triggers here) and 0067 (the capsule descent's landing); read both Implemented paragraphs first.

- Files: `data/sounds/<id>.wav` (16 bit mono PCM, 22050 Hz) listed in `data/sounds/sounds.sjson` as `sounds = [{id, file, volume, kind = "effect" | "loop"}]`; `tools/make_placeholder_sounds.py` (standard library only: `wave` and `struct`, deterministic) writes the first set: footsteps per material (filtered noise bursts: stone, dirt, sand, wood, leaves, snow, metal, water), mining hits per tool tier (clicks getting sharper), a break crunch, a place thud, UI move and confirm blips, one hum loop per machine family (burner, electric, fluid), biome ambience loops (wind, birds, insects, water lapping), a rain loop, the rocket launch rumble, the capsule landing thud, the discovery chime. Sounds are presentation data: a `Sounds` category in `src/data_watch.odin` and `src/hot_reload.odin` reloads the table and files.
- Materials from data: `Block_Definition` gains `sound_material` (default `stone`; set `dirt`, `sand`, `wood`, `leaves`, `snow`, `metal`, `water` on the blocks that need it in `data/blocks.sjson`, the cover blocks `leaves`), validated against the footstep files present in the sound table (`footstep_<material>`).
- Mixer, in a new `src/audio.odin`: `init_audio` after the window (`rl.InitAudioDevice`; when `rl.IsAudioDeviceReady` is false every call is a no op and a log line says so), loads the table (`rl.LoadSound` for effects, `rl.LoadMusicStream` for loops), `play_effect(audio, id, volume, pitch)` with a per id minimum gap of 40 milliseconds so repeats never stack, loops with a per loop target volume the mixer approaches over half a second each frame (`rl.UpdateMusicStream` every frame), so biome ambience crossfades and the rain and the hum fade in and out. Volumes: `master_volume`, `effects_volume` and `ambience_volume` in `Settings` (0 to 1, default 0.8, 1, 0.7) on a new Audio tab of the settings screen (`src/ui_screens.odin`, sliders like UI scale; `SETTINGS_ROW_COUNT` and the tab count grow), applied at once.
- Triggers, in a new `src/sound_events.odin` (pure selection tested, the memory in `Frame_State`): footsteps on the 0066 step detector with the material of the block under the feet and a pitch from a hash of the step count (0.9 to 1.1); mining hits when the mining fraction crosses each quarter, by the effective tool tier; the break sound when the mined counter grows, the place thud when the placed counters grow; UI move when the focus changes and confirm on an activation (`Ui_State` gains a small list of sound events the frame loop drains: `ui_core.odin` records `.Move` on a focus change and `.Confirm` on an activation, `.Back` on back); the hum: the nearest working machine within 12 blocks of the eye (working as the bottleneck markers define it, `marker_means_working`) picks its family's loop, volume falling with the distance; ambience: the player's biome (`sample_column`, as the banner does) maps to a loop through a `ambience` field per biome in `data/biomes.sjson` (`wind`, `birds`, `insects`, `water`, or none), plus the rain loop at the weather's intensity when precipitation falls; the launch rumble when a pad enters `Launching`, the landing thud when a 0067 descent ends, the discovery chime when the quest log gains an `item_discovered` message (the message count in the memory).
- The sparse rule from `DESIGN.md`: nothing plays continuously but the ambience, the rain and one hum; effects are short and never layered beyond the gap rule.
- Tests (`src/audio_test.odin`, `src/sound_events_test.odin`, no raylib): the table parses and every listed file exists, every footstep material has a file, the material of the shipped blocks resolves, hit selection per tier, the step and quarter detectors fire once, the nearest working machine choice and its volume by distance, the biome ambience mapping, the loop volume approach over time, the gap rule, the configuration round trip of the three volumes, the UI audit with the Audio tab.
