# 0293: Water bodies

Status: implementing (2026-11-05)

Milestone: the water tech demo (0291); the water stream after 0292.

## Goal

A connected basin of still water is one record with an integer volume and a level, found by a priority flood over water-capable samples with the radial potential; levelling is instant and exact, a tunnel under a lake fills by construction, the sea is a body of infinite volume with a fixed level, and the cellular rule runs only on the wet front: water pouring into a hole, spilling over a sill at a weir rate, leaving an outlet. Front water that comes to rest on a body is absorbed; front water that goes still in a pit seeds a body. This is water model `bodies` of the tech demo, the browser demo `bodies-waves` (`/home/user/water-demos/notes/basin-bodies.md`, `bodies-front-hybrid.md`, `bodies-waves.md` sections 6 to 9, `chunk-boundary.md`) carried into the field, selected by `World_File_Settings.water_model = bodies`; with `teleport` the field runs 0292's rule unchanged.

None.

## Specification (design, 2026-11-05)

Designed against 0292's specification and its worktree as it stands (`step_field_water` building the passes and the `Field_Water_Search`, `Field_Water_Pressure_Counts`, `water_pressure_failed`, `field_water_share` with the band and `field_water_is_drop`, the test helpers `water_pressure_test_tuning`, `field_water_level_at`, `highest_wet_level_in_column`) and against 0291's (`Water_Model :: enum u8 {Teleport, Bodies}` in `world_chunk.odin`, `World_Settings.water_model`, `Field_Content.tech_demo`); neither has landed. 0291 and 0292 sit on separate branches off `main`, so 0293's worktree made from 0292's tip lacks `Water_Model`: the main agent lands 0291 (or rebases `item/0292` onto it) before 0293's implement starts (question 1 below). The plan `/home/user/water-demos/odin-plan.md` is reused: the fills of a body's samples stay bytes in `Field_Chunk.water`, so the mesher, the codec's fill plane and the chunk hash are untouched; the body table goes to the field tables.

Units as 0292: fill 0..254 a sample, levels in fill units from the centre (`i64`, `field_water_bottom`, `field_water_level`), a body's volume in fill units (the sum of fills). All arithmetic `i64` with `floor_divide_i64`.

### Records (`world_field_water_body.odin`, new; world cluster after `world_field_water.odin`)

```
Water_Body_Id :: distinct u16            // WATER_BODY_SEA :: Water_Body_Id(0), the sea, always alive
Water_Owner :: u16                       // a sample's owner in Field_Chunk.water_owner: WATER_OWNER_NONE 0,
                                         // id + 1 for a body (water_owner_of / water_owner_body),
                                         // WATER_OWNER_RELEASED 0xFFFF the pending flood's old samples
WATER_BODY_BAND :: 16                    // fill units a histogram band, 1/16 sample
WATER_BODY_WEIGHT_SHIFT :: 8             // a cell's slope FIELD_WATER_FULL << 8 / height
Water_Body_Band :: struct { opens, closes: i64 }   // the weights of the cells whose bottom, whose top lies in the band
Water_Body_Frozen :: struct { chunk: Field_Chunk_Coordinate, bands: [dynamic]Water_Body_Band }
Water_Body :: struct {
	alive, sea, dirty, spill_to_sea: bool,
	volume:        i64,                  // fill units; 0 and unused for the sea
	level:         i64,                  // exact fill units from the centre; the sea's is water_planet.sea_level
	written_level: i64,                  // the level the bytes were last written for (write_water_body_fills)
	seed, spill:   Sample_Coordinate,
	spill_level:   i64,                  // the sill; max(i64) sealed or capped (no spill)
	spill_volume:  i64,                  // volume_of_water_body_level(spill_level); max(i64) with no spill
	flood_visits:  i64,                  // a pending flood's spent visits, 0 when none
	base:          i64,                  // band 0's start, the seed's bottom floored to WATER_BODY_BAND
	loaded:        [dynamic]Water_Body_Band,      // the cells in loaded chunks
	frozen:        [dynamic]Water_Body_Frozen,    // per chunk outside the set, coordinate order
	chunks:        [dynamic]Field_Chunk_Coordinate, // loaded chunks holding its samples, coordinate order; derived, not saved
}
Water_Body_Counts :: struct { bodies, front, flood_visits, absorbed, seeded, merged: i64 } // the last tick's, debug only
Water_Flood :: struct { active: bool, body: Water_Body_Id, heap: [dynamic]Water_Flood_Entry, sill: i64, rise_limit: i64, old_chunks: [dynamic]Field_Chunk_Coordinate, seeding: bool }
Water_Flood_Entry :: struct { bottom: i64, sample: Sample_Coordinate }
```

`Field_World` gains `water_model: Water_Model` (set beside every `water_planet` assignment: `enable_new_field_world`, `start_field_world`, `reload_session`, from `state.world.settings.water_model`; the tests set it), `water_bodies: [dynamic]Water_Body` (index = id; `make_sea_water_body` appends body 0 when the model is bodies and the table is empty), `water_flood: Water_Flood` (not saved: rebuilt from `flood_visits`), `water_sea_seeds: [dynamic]Sample_Coordinate` (this tick's samples to claim for the sea, cleared by the step), `water_to_sea: i64` (saved, inflow the sea discarded), `water_body_counts: Water_Body_Counts`. `Field_Chunk` gains `water_owner: [FIELD_CHUNK_SAMPLE_COUNT]Water_Owner` after `water_source` (saved and hashed, see Storage). `destroy_water_body` frees the three dynamic arrays; `destroy_field_world` frees the table and the flood.

Ids: `allocate_water_body_id(world) -> Water_Body_Id` takes the lowest dead slot above 0, else appends; bodies are processed in id order everywhere. A body dies (`alive = false`, arrays cleared) by a merge, when its flood claims nothing, or when a raise buries its seed with no sample left.

The curve. `water_body_band_index(base, level) = floor_divide_i64(level - base, WATER_BODY_BAND)` (clamped at 0: the seed is settled lowest, a dimple below it is folded into band 0). `add_water_body_cell(bands: ^[dynamic]Water_Body_Band, base: i64, span: Field_Water_Span)`: `weight := (FIELD_WATER_FULL << WATER_BODY_WEIGHT_SHIFT) / span.height`, grows the array to the top's band plus one, `bands[band(bottom)].opens += weight`, `bands[band(bottom + height)].closes += weight`; `remove_water_body_cell` subtracts the same. `volume_of_water_body_bands(bands, base, level) -> i64`: `slope, scaled: i64`; for each band k with `start := base + k * BAND`, `if level <= start break; slope += opens - closes; scaled += slope * min(BAND, level - start)`; returns `scaled >> WATER_BODY_WEIGHT_SHIFT`. `volume_of_water_body_level(body, level)` sums `loaded` and every frozen part (one base). `water_body_capacity(body)` is the volume at `base + BAND * (longest array)`. `body_level_of_volume(body: ^Water_Body, volume: i64) -> i64`: the largest `level` in `[base, top]` with `volume_of_water_body_level(body, level) <= volume`, by a binary search (at most 20 halvings: the range is under 2^20 for `flood_rise_samples` 64); `top` when the body is over full (a sealed basin holds the excess as volume). Both are integer, monotone and each other's inverse to one fill unit of level, which is what the pump test asserts.

### The flood (`flood_water_body`)

`settle_water_body_seed(world, seed: Sample_Coordinate) -> Sample_Coordinate`: up to 8 rounds of a breadth-first walk from the seed through non-ground samples of loaded chunks whose bottom is under the seed's bottom plus its height (one slab), at most `WATER_BODY_SETTLE_VISITS` (256) a round, taking the lowest by `(bottom, field_sample_before)`; stops when no lower sample is found. The sphere's `bottom` has one-cell dimples; a flood from a dimple above the floor spills after one cell.

`start_water_body_flood(world, id, tuning)`: `flood = {active = true, body = id, seeding = body.volume == 0 && len(body.loaded) == 0}`; `old_chunks` = a copy of `body.chunks`; a sweep over them turns every `owner == id + 1` into `WATER_OWNER_RELEASED` (the old samples stay the body's until the flood ends: `water_owner_body` maps RELEASED to `flood.body`); `body.chunks`, `body.loaded` cleared; if the seed's sample is ground, the seed becomes the lowest RELEASED non-ground sample of `old_chunks` (`(bottom, sample order)`), and with none the body dies with its volume added to `world.water_dropped` (a lake walled solid); else `seed = settle_water_body_seed`; `base = floor to BAND of bottom(seed)`, `sill = bottom(seed)`, `rise_limit = bottom(seed) + i64(tuning.flood_rise_samples) * FIELD_WATER_FULL`; `spill_level = max(i64)`, `spill_to_sea = false`; the heap holds the seed. A binary min-heap of its own (`push_water_flood`, `pop_water_flood`, keyed `(bottom, field_sample_before)`), so the order never depends on a library.

`run_water_body_flood(world, tuning, budget: ^i64) -> (done: bool)`, one visit per pop while the heap is not empty and `budget^ > 0` (`budget^ -= 1` per pop; `body.flood_visits += 1`), `e := pop`, `chunk := world.chunks[chunk of e.sample]` (only loaded samples are pushed), `owner := chunk.water_owner[index]`, `span := field_water_span(e.sample)`, `bottom := field_water_bottom(span)`:

1. `owner == id + 1`: already claimed (pushed twice), continue.
2. `bottom > flood.rise_limit`: the heap's minimum passed the cap: stop, no spill (`spill_level = max(i64)`), done.
3. `owner == WATER_OWNER_SEA` (the sea's, 1): the spill: `spill = e.sample`, `spill_level = max(sill, bottom)`, `spill_to_sea = true`, done.
4. `bottom + span.height <= sill` (the slab wholly under the running sill: beyond a saddle): `spill = e.sample`, `spill_level = sill`, done. The weir hands water there; another body's water lying there takes it straight (The weir).
5. `owner` is another live body B (not RELEASED) and the sample is B's wet one (`bottom < B.level`): `sill <= body.level` (connected under our water) merges B: `body.volume += B.volume`, B's frozen parts appended (rebased: both bases are multiples of BAND, the lower wins and the other's bands shift by the difference; `rebase_water_body_bands`), B's loaded samples turned RELEASED by a sweep over `B.chunks` (they are re-claimed through connectivity), `B.chunks` appended to `old_chunks`, B dies, `counts.merged += 1`; then claimed as step 6. Otherwise (B's water stands above ours: it will spill to us) a wall: continue. A dry sample of B (its air above its level) is simply claimed.
6. Claim: `sill = max(sill, bottom)`, `owner = id + 1`, `add_water_body_cell(&body.loaded, base, span)`, the chunk into `body.chunks` (sorted insert), `note_field_chunk_change`; expand the six neighbours in slot order: skip `chunk == nil` unless the missing sample is sea (`field_missing_sample_sea > 0`: the basin reaches the sea outside the set: `spill = e.sample`, `spill_level = max(sill, bottom(neighbour))`, `spill_to_sea = true`, done), skip ground (`density > 0`) and `owner == id + 1`; push the rest (unowned, RELEASED, the sea's, other bodies': they are judged when popped).

When the heap empties without a spill, `spill_level = max(i64)` (a sealed basin). `budget` exhausted with the heap not empty returns false; the heap stays, `body.dirty` stays, the next tick resumes. The budget is checked per pop, so a tick never overruns it.

`finish_water_body_flood(world, body, tuning)`: sweep `old_chunks`: every RELEASED sample gets owner 0 and, when its byte is above 0, `body.volume -= byte` and `wake_field_water_sample` (it is front water now: the split, exact in one call); `spill_volume = spill_level == max(i64) ? max(i64) : volume_of_water_body_level(body, spill_level)`; for a seeding flood `absorb_seeded_front(world, body)`: `volume` = the fills of the owned awake samples whose `water_still > 0` (resting), `level = body_level_of_volume`, then the owned awake samples with `bottom < level` add theirs too (under the surface), each absorbed sample sleeping (water falling through the basin's air above the level keeps falling; the study's revision 6, item 3); else `level = body_level_of_volume(body, volume)`; `write_water_body_fills(world, body, force = true)`; `dirty = false`, `flood_visits = 0`, `flood.active = false`; a body with `len(loaded) == 0` dies (its volume to the front already). `counts.flood_visits` sums the visits.

`write_water_body_fills(world, body, force)`: returns unless `force` or `floor(level / BAND) != floor(written_level / BAND)` (the bytes follow the level a band at a time, which is what keeps a filling lake from rewriting its area every tick); sweeps `body.chunks`, every sample with `owner == id + 1` gets `field_sea_fill(body.level, span)` (the fill under the level, the very expression the sea uses) through `write_field_water_quiet(world, chunk, index, sample, fill)` (new, in `world_field_water.odin`: the byte, `note_field_chunk_change`, `mark_field_chunks_around_sample_dirty`, `edited_chunks`; no wake; nothing when the byte is unchanged), then `written_level = level`. Ownership and the bytes are rewritten only here, in the flood and in the absorption, so a body's sample is always asleep with a derived byte.

`reflood_dirty_water_bodies(world, tuning)`: `budget := i64(tuning.flood_visit_budget)`; the active flood first (`run_water_body_flood`, finishing when done), then every alive non-sea dirty body in id order: `start_water_body_flood`, run, finish or leave pending; stops when the budget is spent. At most one flood is pending at a time.

### The sea (body 0)

Fixed `level = water_planet.sea_level`, no volume, never flooded, never merged, never spills. Its samples are every non-ground sample with `field_sea_fill > 0` connected to the sea: `generate_field_chunk` (`fill_field_chunk_sea`) sets `water_owner = WATER_OWNER_SEA` wherever it gives a sea fill (model-agnostic: under teleport the plane is written and never read), so a pristine coastal chunk equals its generation and a missing chunk's ownership is the generation's, as its fill is today. `claim_sea(world)`: a breadth-first walk from `water_sea_seeds` through non-ground samples of loaded chunks with `field_sea_fill(span) > 0` whose owner is 0 or a body's (never RELEASED: a pending flood's samples wait for its end), seeded only from samples beside a sea-owned sample or a missing sea sample; each claimed sample: an owned one's body loses the sample (`remove_water_body_cell`, the body dirty), a front fill is counted into `water_to_sea`, then `owner = SEA`, byte `field_sea_fill(sea_level, span)` through `write_field_water_quiet`, sleep. Seeds come from edits (a dug sample below sea level, or a wet sample beside one) and from `field_world_insert_chunk` under bodies: the arriving chunk's face samples beside a loaded sea-owned sample or a missing sea sample (`field_face_pairs`), so a version 4 chunk is claimed as it enters. Inflow into a sea sample (the flux, absorption, a weir into the sea, a spring the sea owns) goes to `water_to_sea`. The sea edge refill of `field_water_source_fill` does not run under bodies (the claim owns those samples).

### The step (`world_field_water.odin`)

`step_field_water(world, tuning, tick)` keeps its signature and dispatches: `.Teleport` runs 0292's body unchanged (renamed `step_field_water_teleport`), `.Bodies` runs `step_field_water_bodies`. `finish_field_tick` does not change. The front is the awake set: an awake sample whose owner is not 0 (a body's, the sea's, RELEASED) is slept at once by the pass (`water_flow = 0`) except a spring, which stays awake and credits `tuning.rate` a tick into its owner (`volume += rate`, counted in `counts.absorbed`; the sea's into `water_to_sea`: the sea never rises). `field_water_can_wake` and `wake_field_water_sample` refuse an owned sample when `world.water_model == .Bodies`, so a lake is never woken by its shore.

`step_field_water_bodies`, in order:

1. `world.water_body_counts = {}`; `claim_sea`; `reflood_dirty_water_bodies`; `emit_water_body_weirs`.
2. The passes as 0292 builds them (chunks in coordinate order, `awake` and `start` copied), kept in `passes: map[Field_Chunk_Coordinate]^Field_Water_Pass` as well as the slice; `Field_Water_Pass` gains `delta: [FIELD_CHUNK_SAMPLE_COUNT]i16` and `outflow: [FIELD_CHUNK_SAMPLE_COUNT]u8`; `pass_for(world, passes, chunk) -> ^Field_Water_Pass` adds one lazily for a receiving chunk with no awake sample (`awake = {}`, `start = chunk.water`), appended to the slice in creation order (pass two sorts the slice by coordinate before applying). `inflow: [dynamic]i64` indexed by body id, zeroed.
3. Pass one, `plan_field_water_sample(world, passes, pass, index, tuning, tick)` for every awake sample in order: ground sleeps as today; an owned sample sleeps (the spring rule above); a spring refills its start to full in `pass.start` and the byte (`set_field_water`); a film (`field_water_is_film` on the start fills) dries as 0292 (`dry_field_water_film`) and plans nothing; else for the six neighbours, nearer the centre first then the others, `amount := field_water_share_from(span, sender_start, neighbour.span, receiver_start, room, tuning, left)` where `sender_start = pass.start[index]` (the tick-start fill, the levels compared from it on both sides) and the sender's `left` starts at the same and falls with every planned amount (so a sample never overspends); `receiver_start` is the neighbour's `pass.start` (its byte when it has no pass; `neighbour.sea` for a missing sea sample, which takes nothing: room 0 under bodies, a missing chunk is a wall); `room = FIELD_WATER_FULL - receiver_start - delta already promised to it` (so no receiver overfills and no return path is needed). `field_water_share_from` is the pure core of 0292's `field_water_share` (the difference of the exact levels from the two fills, the band or the drop, the equalising rounding, the caps) and `field_water_share` calls it with the bytes, so the teleport rule is unchanged. Each amount: `pass.delta[index] -= amount`, `outflow += amount`; the receiver: a body's or the sea's sample credits `inflow[body] += amount` (the sea's into `water_to_sea`) and still counts against its room; a front sample's `delta[receiver] += amount` in its pass.
4. Pass two, chunks in coordinate order, indices in order: `delta != 0` applies through `set_field_water(byte + delta)` (wakes the neighbours, which is how the front spreads); `water_flow = outflow`; the still ticks of an awake front sample: `delta == 0 && outflow == 0 && byte == start` adds one (capped 255), else 0. Then `bodies[id].volume += inflow[id]` for every id (`counts.absorbed` sums them), `write_water_body_fills(force = false)` for each.
5. Absorb and seed, `settle_field_water_front(world, passes, tuning)`: over the passes' awake samples again in order, skipping ground and samples already asleep: with fill above 0, (a) the nearer-centre face neighbours in slot order: one owned by a body B (not RELEASED, not the pending body) with `bottom(neighbour) < B.level` absorbs the sample: `B.volume += fill` (the sea: `water_to_sea`), `owner = B` (added to `B.loaded` and `B.chunks` when it was unowned: a rim cell above the sill a lake at its sill wets), byte `field_sea_fill(B.level, span)`, sleep, `counts.absorbed`; (b) else owned by B itself with `bottom < B.level`: the same; (c) else `water_still >= tuning.still_ticks`: owned by B (its dry air): absorbed into B as (a); unowned: a seed candidate `(bottom, sample)`. The candidates sorted by `(bottom, field_sample_before)`; each in turn while the flood budget of this tick is not spent and no flood is pending: `seed_water_body(world, sample, tuning)`: a new id, `seed = sample`, `dirty = true`, `start_water_body_flood`, run, finish or pending (`counts.seeded`). A candidate not seeded stays awake (its still ticks capped) and is retried next tick: the budget postpones, never drops.
6. Sleep: a front sample with `water_still >= still_ticks` that was neither absorbed nor seeded (a sealed budget tick) keeps the awake bit, as 0292's postponed samples do. The passes' chunks with no awake bit leave `water_awake_chunks`.

Stillness is "no flux through the sample" (the study's item 5): a steady drip has `delta == 0` with `outflow > 0` and never seeds.

### The weir

`emit_water_body_weirs(world, tuning)`, alive non-sea bodies in id order, not dirty and not pending, with a spill: `excess := volume - spill_volume`; nothing while `excess <= i64(tuning.weir_dead_band)` (the static friction is on the head, not on the cells); else `head := level - spill_level` (fill units), `flow := min(excess, max(i64(tuning.weir_floor), min(i64(tuning.weir_cap), i64(tuning.weir_rate_per_head) * head / FIELD_WATER_FULL)))`; the spill sample: `spill_to_sea` or its owner the sea: `water_to_sea += flow`, `volume -= flow`; owned by another body B: `B.volume += flow`, `volume -= flow`, and when `B.level >= spill_level` (B's water reached the sill) and `excess - flow <= weir_dead_band` (we sit at our sill) B is merged into the lower id (`merge_water_bodies(world, lower, higher)`: as step 5's merge, then the survivor `dirty`); a front sample (unowned, or the spill chunk missing: skip): `flow = min(flow, room of its byte)`, `set_field_water(byte + flow)` (wakes it: the stream starts), `volume -= flow`. The spill sample lies beyond the saddle, so a front sample there is never re-absorbed by (a): its lower neighbours are not the body's wet samples (the study's item 2). `write_water_body_fills(force = false)` after a change of level.

### Edits and displacement

`follow_field_terrain_with_water` under bodies: a sample turned ground that was a body's: `volume -= byte`, owner 0, byte 0 (no push to the neighbours: the body re-levels), the body dirty; the sea's: owner 0, byte 0; unowned wet: `displace_field_water` as today, except that a receiving neighbour owned by a body credits its volume instead of its byte. Then, for the sample and its six loaded face neighbours: each owner that is a body is marked dirty (a hole beside or under a lake re-floods it this tick: the step runs after the drain); a sample now air with `field_sea_fill > 0` beside a sea-owned or missing sea sample goes to `water_sea_seeds` (a dig below sea level connected to the sea fills in the same tick, before the front runs). `wake_field_water_around` as today (owned samples refuse). `displace_water_body_volume(world, id, amount: i64) -> i64` (0295's stub: `volume = max(0, volume - amount)`, the level and the bytes follow, returns what was taken) sits in the body file for the pump test.

### The simulated set's edges

`field_world_remove_chunk(world, coordinate)` (new in `world_field.odin`; `unload_left_field_chunks` calls it in place of its destroy and delete, then the existing `wake_field_water_beside_missing` loop): under bodies, `freeze_water_body_chunk(world, chunk)` first: every body with the coordinate in `chunks` gets a frozen part built by a sweep over the chunk (`owner == id + 1`: `add_water_body_cell` into the part and `remove_water_body_cell` from `loaded`, the same cells so the level is exact and unchanged), the chunk removed from `chunks`; a body whose seed lies in the chunk moves its seed to the lowest owned sample of its remaining chunks (`(bottom, sample order)` sweep) or, with none, keeps it and sleeps wholly frozen (no floods, no weir: the weir skips a body whose spill chunk is missing); a pending flood touching the chunk restarts (`flood_visits = 0`, the heap dropped, RELEASED samples stay, `dirty` stays). The leaving chunk is saved whole as today with its owner plane. `field_world_insert_chunk` under bodies: `thaw_water_body_chunk(world, chunk)`: every body with a frozen part for the coordinate drops it and takes the chunk's owned samples back into `loaded` by a sweep (the inverse of the freeze: the bytes carry the ownership), the chunk into `chunks`, the body `dirty` (the wall is gone: the re-flood may find a lower sill or a merge); then the sea seeds of the arriving chunk's faces (The sea); then `wake_field_water_facing` as today (a body's samples refuse). The awake bits of a parked front travel in the chunk's bytes already, so a stream resumes where it stopped. A lobe of a lake joined to its seed only through a missing chunk is re-flooded as a body of its own (its old samples hand their fill to the front, which settles and seeds; exact volume, the level wrong until the chunk returns and the floods merge them): the study's known limit, accepted.

### Storage, codec, hash

- `Field_Chunk.water_owner` is saved and hashed: it is state the tick reads (the flux, the absorption, the sea claim) that a returning chunk must bring back, and a derived plane would need every lobe's seed, which only the plane holds. Codec: `FIELD_CHUNK_FORMAT_VERSION` 5, `FIELD_CHUNK_PLANE_COUNT` 11: after the source bits, the owners' low bytes and high bytes as two planes (each run length encoded; a teleport world's are two runs), then the light. `decode_field_chunk_delta` reads 4 (nine planes, the owner plane zero: a chunk saved before 0293; the sea claim and the front rules remap it on arrival, Old saves below) and 5; others refused by number as today. `field_chunk_terrain_and_water_equal` and `field_chunk_equals` compare the plane; `field_chunk_state_hash` fingerprints it after the source bits; the head comments of the codec and the hash name it. The crater overlay path is untouched.
- The body table, `write_water_body_table(bytes, world: ^Field_World)` and `read_water_body_table(reader, world) -> bool` in `simulation_field_save.odin`, written after the arrival table in `write_simulation_state` (field worlds only) and read after `read_field_arrival_table`: `append_u64(water_to_sea)`, then `write_list` of `Water_Body_Record {id: u16, alive, sea, dirty, spill_to_sea: bool, volume, level, written_level, spill_level, spill_volume, flood_visits, base: i64, seed, spill: Sample_Coordinate}` in id order (dead slots included, so ids keep their meaning), then `write_list` of `Water_Body_Band_Record {body: u16, frozen: bool, chunk: Field_Chunk_Coordinate, band: i32, opens, closes: i64}` (every nonzero band, bodies in id order, the loaded bands then the frozen parts in coordinate order, bands ascending). The reader rebuilds the arrays; it refuses a band record naming a dead or unknown body, a negative band, or more than one sea. `body.chunks` is rebuilt after the set restores (`rebuild_water_body_chunks(world)`, a sweep of the restored chunks' planes, called from `restore_arrived_field_set`), and a pending flood is resumed there too: `resume_water_body_flood_after_load(world, tuning)` restarts the one dirty body with `flood_visits > 0` and runs it for exactly that many visits without the budget. The flood is a pure function of the terrain, the owner plane (RELEASED and claimed samples saved as they stood) and the visit count, so the loaded machine holds the saving machine's heap and finishes on the same tick. Being in `entities.bin`, the table is in `simulation_state_hash` by value, in id order; the heap and `chunks` are derived and not hashed.
- Old saves: a field save ending before the table (written before 0293) loads with no bodies and one log line, `save: written before the water bodies (0293), the water settles into bodies over the first ticks`; under bodies `make_sea_water_body` adds the sea, every version 4 chunk's sea is claimed as it enters (the arrival's face seeds), and its other wet samples wake on entry (`wake_field_water_facing` and a sweep of the unowned wet asleep samples when the chunk's bytes were version 4: `decode_field_chunk_delta` returns `(problem: string, old_owner_plane: bool)` and `insert_field_chunk_arrival` wakes them), so they settle and seed bodies by the normal rule with their volume conserved as front water. A teleport world reads the plane and ignores it. No remap beyond that; the tech demo never saves, so such a save is a developer's.

### Data

### Hand-back check

- Range checks: the six keys through `field_water_problem`; `read_water_body_table` refuses malformed records; `decode_field_chunk_delta` validates the plane lengths as the others.
- Save layout: a save without the table loads with the log line above and the water settling into bodies by the normal rules; version 4 chunks read with a zero plane. The tech demo never saves.
- Shared budget: `flood_visit_budget` is spent in order (the pending flood, dirty bodies by id, then seeds by `(bottom, sample)`); a seed or a dirty body left over is retried next tick and never dropped; a pending body keeps its old samples and level, and nothing absorbs into it until it finishes.
- Bounded lists: the heap holds at most six entries a visit plus one; `water_bodies` grows by the lowest dead slot; the sea claim is bounded by the connected sea samples of the set (each claimed once); `write_water_body_fills` runs once a band.
- Tests use worlds in memory only; the save test writes to a byte buffer.

### Decisions on the open points

- The owner plane is saved and hashed (Storage), not derived: the alternatives were weighed there. Cost: 64 KiB a chunk in memory (question 2).
- The sea is body 0 and never floods; its ownership is the generation's plus the connected claim; a lake below sea level joined to the sea is the sea.
- The volume-level curve is a band histogram of opened and closed slopes (16 fill units a band), exact for the bucketed cells and its own inverse; the loaded part is rebuilt by every flood and the frozen parts at unload, one base per body.
- The bytes of a body's samples follow the level a band at a time; the conserved quantity is the body volumes plus the front's fills, never the bytes.
- Merges keep the lower id and re-flood the union; splits hand the unreached old samples to the front, exact in one call; a seed buried by a raise moves to the body's lowest sample.
- A pending flood is the one piece of in-memory state, restored by replaying its visit count.
- A missing sea sample met by a flood is a spill into the sea; any other missing sample is a wall, as 0292 decided.
- Films dry as 0292's rule under bodies too (the drying is the only non-conserved sink, as today); the breach tests set `dry_ticks` beyond their run.
- `weir_floor` and `flood_rise_samples` are keys beyond the item's list: the floor ends the exponential tail (the study's revision 5b), the cap bounds an open basin's flood (the demo's MAXRISE; without it a crater's air to the rim is the flood, and a flat plain's the whole set).
