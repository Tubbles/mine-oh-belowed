# 0319: raylib 6.2

Status: implementing (2026-11-11)

0315 floated the toolchains and left raylib pinned at 6.0, with the reason in `tools/build_raylib.sh`: the committed Linux and Android archives and `windows/raylib.lib` are built from the tag, the Android one with three patches, and `shared/raylib`'s binding is a copy. raylib 6.2 (2026-10-15) contains `a005a044d`, the upstream fix of the third patch, and Odin dev-2026-11's `vendor:raylib` binds 6.2.

## Goal

The game runs on raylib 6.2 on the desktop, under Wine and on the phone, with only the patches 6.2 still needs.

## Controls

None.

## Change

- `tools/build_raylib.sh` builds 6.2. The third patch is dropped, and the other two are checked against 6.2's source.
- The three archives are rebuilt. The binding in `shared/raylib` is copied from Odin's `vendor/raylib` at the release in `~/opt/odin`, with the repository's changes to it carried over.
- What changed between 6.0 and 6.2 that the game uses (input, the GL ES path, audio) is read from the release notes, and each change is checked.
- Docs: `doc/build.md` (the toolchain table, The shared collection), `shared/raylib/README.md`, `doc/android.md` (raylib for Android).

## Verify

- The checks and the suite.
- The couch, the Windows build under `tools/wine_smoke_test.sh`, and the phone: starts, the title, a field session, the touch overlay.

### Patches

- 0133 key queue: kept as is.
- 0236 gamepad source bits: dropped, upstream in 6.2. Delete `patch_android_gamepad_source_bits`, its comment, its call and its record line.
- 0126 precision: narrowed. `patch_default_shader_precision` rewrites, in `src/rlgl.h`, the one block that follows `"#version 300 es` in the fragment shader (`"#ifdef GL_FRAGMENT_PRECISION_HIGH`, `"precision highp float;`, `"#else`, `"precision mediump float;`, `"#endif`) into the single `"precision highp float;` line; the vertex `#version 300 es` line is followed by its `highp` line and is left; the ES2 block follows `#version 100` and is left. Anything but one rewrite fails. The awk, tried on 6.2's `rlgl.h` (one rewrite, the diff removes exactly the four lines):

```
awk '
	/^[ \t]*"#version 300 es[ \t]*\\n"$/ {
		print
		if ((getline line) <= 0) { failed = 1; exit }
		if (line !~ /^[ \t]*"#ifdef GL_FRAGMENT_PRECISION_HIGH[ \t]*\\n"$/) { print line; next }
		if ((getline highp) <= 0 || highp !~ /^[ \t]*"precision highp float;[ \t]*\\n"$/) { failed = 1; exit }
		if ((getline other) <= 0 || other !~ /^[ \t]*"#else[ \t]*\\n"$/) { failed = 1; exit }
		if ((getline mediump) <= 0 || mediump !~ /^[ \t]*"precision mediump float;[ \t]*\\n"$/) { failed = 1; exit }
		if ((getline closing) <= 0 || closing !~ /^[ \t]*"#endif[ \t]*\\n"$/) { failed = 1; exit }
		print highp
		rewrites++
		next
	}
	{ print }
	END { if (failed || rewrites != 1) exit 1 }
' "$header" > "$header.new"
```

  Error text: `rlgl.h: expected one OpenGL ES3 default fragment shader precision block`. Its comment says why: 6.2 makes the vertex shader `highp` and the fragment shader `highp` only under a macro GLSL ES 3.00 does not predefine; Mali's `mediump` is 16 bit (0126).

### Questions to the main agent

1. Precision patch: keep narrowed (recommended, the phone keeps what 0126 tested; GLSL ES 3.00 does not predefine the macro) or drop it and trust the phone's driver to define it.
2. The cursor fixes (Android guard, two pre-loop polls) restore 6.0's zero delta lost by #5962; recommended in this item, since the phone case turns the view with the overlay Off. Without them the hand-checks above are where it would show.
3. raylib stays pinned, now at 6.2, with the reason updated: the archives and the binding copy are committed and patched, so it cannot float per build. Recommended.

### Decisions (main agent, 2026-11-11)

1. The precision patch stays, narrowed to the ES3 fragment shader's block, so the phone keeps the `highp` 0126 tested.
2. The cursor fixes (the Android guard in `apply_cursor_mode`, the two polls before the loop) are part of this item: they keep 6.0's behaviour, and the phone case turns the view with the overlay Off.
3. raylib stays pinned, at 6.2, with the reason in `tools/build_raylib.sh` as step 1 words it.
4. The Android archive is built only with `--android --host` inside the existing container. If the script or a container asks to install or download anything beyond step 5's zip, the implementer stops and reports.
5. `CLAUDE.md`'s Stack line follows at the landing.
