# 0091 Recipe browser: have and need, unlocked only, the missing glyph

Status: implemented
Milestone: M11

## Goal

Couch report (2026-09-28): the recipe page should say how much of each ingredient the player has ("13/5 stone", not "5 stone"), it needs a filter for unlocked recipes only, and with the Oxanium font the ingredient line reads "1 ? Concrete".

## Deliverables

- Ingredient rows (`draw_stack_rows` in `src/ui_recipes.odin`) read "13 / 5 Stone" (have, then need, then the name) with the have count in the accent colour when it covers the need and the danger colour when it does not, and the detail panel says how many crafts the inventory covers ("Can craft 2"). Output rows keep the count and the name.
- A filter toggle "Unlocked only" in the browser's filter row (`Recipe_Filter` in `src/recipe_browser.odin` gains `unlocked_only`, default on; the existing available flag decides), remembered per session.
- The missing glyph: the multiplication sign in code formats (`src/ui_recipes.odin`, `src/technology_browser.odin`, `src/ui_contracts.odin`) is not in the string table, so the font cache never loads it and Oxanium shows "?". Move those formats into `data/strings/en.sjson` keys with `{count}` and `{name}` marks (`format_message_text`), which loads the glyph with the rest, and add a test in `src/data_strings_test.odin` that every non ASCII code point in the string table exists in every shipped font family (`src/ui_font.odin` can read a font's glyph set through the loader used for the atlas, or the test lists the code points and the loader checks them at start and logs a missing one).
- Tests: the have and need text, the craft count, the filter, the glyph audit.
- Docs: `doc/ui.md`, `doc/log/2026-09-28.md`, this item.

## Verify

- Builds and tests pass.
- User: the stone furnace row reads "13 / 5 Stone"; the filter hides locked recipes; no "?" in Oxanium.

## Implemented

`crafts_covered` (`src/recipe_browser.odin`), `filter_showing_recipe` with an `available` parameter, `make_recipe_browser` with unlocked only on; `draw_ingredient_rows`, `ingredient_line`, `ingredient_color`, `can_craft_text`, the "Unlocked only" toggle in `recipe_filter_column`, `navigate_to_recipe` taking the unlocks, and `stack_line` from `recipes_stack_line` (`src/ui_recipes.odin`); `technology_cost_text` from `technologies_cost_line` (`src/technology_browser.odin`). Tests: `test_crafts_covered`, `test_default_filter_hides_locked_recipes`, `test_graph_step_to_a_locked_recipe_drops_unlocked_only`, `test_recipe_detail_lines` (`src/recipe_browser_test.odin`), `test_technology_cost_text` (`src/technology_browser_test.odin`), `test_recipe_screen_shows_have_and_need` (`src/ui_audit_test.odin`), and the glyph audit `test_shipped_fonts_have_every_string_glyph` (`src/ui_font_test.odin`). The audit reads each font file's cmap (`font_glyph_index`) instead of calling `rl.LoadFontData`, since any raylib call makes the test link need X11 (see `doc/log/2026-09-28.md`); it failed for every family with U+1F600 and U+4E00 added, then those were removed.

## Notes

Implementation pointers, decisions taken so the item is unambiguous (main agent, 2026-09-28):

- Have and need: `draw_stack_rows` (`src/ui_recipes.odin`) stays for the outputs; the inputs get `draw_ingredient_rows(state, content, label, stacks, items, inventory)`, one row per ingredient reading the string `recipes_ingredient_line = "{have} / {need} {name}"` (have is `inventory_count`) through `replace_message_mark` (`src/quest_runtime.odin`) for the three marks, the row in the theme's `.Accent` colour when have covers need and `.Danger` when it does not. Under the inputs a detail line `recipes_can_craft_count = "Can craft {count}"` with `crafts_covered(inventory, recipe) -> int` (new, pure, `src/recipe_browser.odin`: the smallest have divided by need over the inputs, a recipe without inputs counts as 0), accent when at least 1, dim at 0. Locked recipes (silhouettes, `detail.revealed` false) show neither, as today.
- Unlocked only: the flag is the existing `Recipe_Filter.available_only`; `make_recipe_browser` sets it on, so the default hides locked recipes, and a toggle `recipes_unlocked_only = "Unlocked only"` next to "Can craft now" binds it. `selection_filter` keeps setting it. `filter_showing_recipe` gains an `available: bool` parameter and drops `available_only` when the recipe reached through the graph is locked, as it drops the craftable filter; its caller in `src/ui_recipes.odin` passes `recipe_is_available`. Remembered per session by the browser, as the other filter fields are.
- The glyph: the two formats holding the multiplication sign are `stack_line` (`src/ui_recipes.odin`, also used by `contract_reward_text` and `catalogue_entry_label` in `src/ui_contracts.odin`) and `technology_cost_text` (`src/technology_browser.odin`). They become string keys `recipes_stack_line = "{count} × {name}"` and `technologies_cost_line = "{count} × {seconds} s  ({packs})"` filled with `replace_message_mark`, so the sign is in the string table, which `collect_code_points` (`src/ui_font.odin`) feeds to every font load. Keep the two procedures' names and return values, so their tests only change where the text does.
- The glyph audit, in `src/ui_font_test.odin`: for every shipped family's regular and bold file (`load_fonts` on `test_data_directory()`, `font_file_path`) load the file with `rl.LoadFileData` and its glyphs with `rl.LoadFontData(data, size, 32, code_points, count, .DEFAULT)` for the non ASCII code points of the shipped string table (`collect_code_points` on `data/strings/en.sjson`, the entries after `LAST_ASCII_CODE_POINT`), both CPU only, no window; every returned glyph must have image data (`image.data != nil`, the way raylib leaves a code point the font lacks empty), named in the failure message with the family and the code point; free with `rl.UnloadFontData` and `rl.UnloadFileData`. Do not import `vendor:stb/truetype`: the toolchain ships no Linux library for it. If `LoadFontData` turns out to render something for a missing glyph, compare each glyph's image bytes with the glyph raylib renders for U+FFFD or a code point the font surely lacks, and report the check used. The test must fail on the string table before this change if `×` were absent from a family; verify it fails by temporarily adding a code point no font has (for example U+1F600) to the test's list, then remove that.
- Tests: `src/recipe_browser_test.odin` (`crafts_covered`, the default filter hides locked recipes and the toggle shows them, `filter_showing_recipe` drops `available_only` for a locked target), the ingredient line text and the two formats (`src/ui_format_test.odin` if `replace_message_mark` helpers land in `src/ui_format.odin`, else next to their procedures' tests), the glyph audit, and `src/ui_audit_test.odin`: the recipe screen with a focused unlocked recipe draws a "/" have and need row and the "Unlocked only" toggle (`draw_list_has_text`), the bounds audit keeps passing.
- Docs: `doc/ui.md` (the recipe browser paragraph: have and need, can craft, the filter), `doc/log/2026-09-28.md` (the decisions above, and that the glyph audit guards the string table), this item's Status and an Implemented paragraph.
