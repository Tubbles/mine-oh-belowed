# User interface system

How every screen in the game is built, so that the pillars "couch first" and "one coherent game" hold from the first panel. The screen list itself is in [DESIGN.md](../DESIGN.md).

## Principles

- 10 foot UI. Body text is at least 24 pixels at 1080p, headings 32, the glyph bar 28. Everything scales with screen height and a user UI scale setting. A five percent safe area keeps content away from television edges.
- Two navigation styles, one model. Every interactive widget has a rectangle and a stable id. A focus cursor moves between widgets with the d-pad or left stick using a spatial rule in two passes (0093, `find_focus_neighbour`): first the nearest widget ahead in the focused widget's row (left and right) or column (up and down), that is a widget of the same panel whose extent across the direction overlaps the focused one's, ties to the smallest sideways offset; only when that finds nothing, the nearest widget in the pressed direction with the sideways offset weighted double, wrapping inside the panel. The pointer (right trackpad or mouse) sets focus to whatever it hovers, so both styles drive the same focus state and every screen works fully with either. Confirm is A or a tap (Pointer, below; item slots take a drag instead, Item slots with a pointer), Back is B, tabs are the bumpers, Y opens the info panel, X is the panel's context action (sort, split). A screen opened from the world starts with the focus on the widget it prefers (`ui_prefer_focus`, the fallback in `ui_resolve`), else on its first widget (0094): the inventory and every machine panel prefer the hotbar slot selected in the world; the pointer is unaffected. The focus a screen had is forgotten on the first frame without a screen (`run_screens`), while a screen pushed over another keeps it.
- No hover only information. Tooltips are panels that open on Y and dock to the edge of the current panel. Item slots (0094) show their stack's info tooltip by themselves once the focus, or the pointer, which focuses what it hovers, has rested on the slot for `UI_TOOLTIP_DELAY` (0.4 seconds), and it goes when the focus moves; an empty slot shows none, and there is no setting to turn it off. The Info hint left the slot views' glyph bars; Y still toggles the info panel for every widget.
- Radial menus for quick choices: the hotbar, categories, the letter wheel. Shown while the pad is touched, highlight follows the finger angle, release selects, the dead centre cancels.
- Text only from data. Every player facing string comes from `data/strings/en.sjson` by key. Numbers go through one formatting procedure per unit (per minute, kW, MW, L, blocks).
- Stick repeat: 350 ms initial delay, then 80 ms per step, for held directions in lists and grids.

## Architecture

- An immediate mode UI written in Odin over raylib draw calls. raygui is not used: it is mouse centric and has no focus navigation.
- Per frame: `ui_begin` resets the frame, screens declare widgets (each call returns the widget's interaction result for this frame), `ui_end` resolves focus movement and pointer hover, then draws from a deferred command list so that focus resolved this frame is drawn this frame. Activation is decided inside the widget call (Confirm on the previous frame's focus, or a tap whose release is hit tested this frame, Pointer below; an item slot takes the release of a drag instead, Item slots with a pointer), so results arrive without delay; only focus moves show up in widget results one frame late. The UI runs after the simulation in the frame, so a screen opening or closing reaches the world one frame later, and a world action still held when a screen closes stays suppressed until it is released.
- One `Ui_State` in the frame state: focus id, focus panel, per widget scroll offsets and selections keyed by id, the open screen stack, radial state, repeat timers, the pointer position and whether the pointer or the sticks moved last (the glyph bar shows what fits the active device).
- Layout in UI units where 1080 units span the screen height; conversion to pixels happens in the draw layer. The pixels are render pixels (0085), the framebuffer's `GetRenderWidth` by `GetRenderHeight`: with the high DPI flag on a scaled Wayland desktop they are the panel's, 1.7 times the window's size at 170 percent, so text rasterises at the panel's pixel size. The 2D passes (the UI, the diagnostics pages, the underwater overlay) reset raylib's modelview to the identity first (`begin_render_pixel_drawing`), since raylib multiplies its DPI scale in, and UI clips go through rlgl rather than `BeginScissorMode`, which scales its box too. The mouse position enters in render pixels: raylib's mouse scale is reset to 1 every frame and GLFW's cursor, in the window's coordinates, is scaled per axis by the framebuffer's size over GLFW's window size (`pointer_to_render_pixels`); the mouse delta for looking stays in window coordinates. The trackpad pointer moves in UI units and needs no mapping. On X11 at scale 1 all of this is the identity. Rows, columns and grids compute rectangles with a small set of layout helpers; no constraint solver.
- Drawing: rectangles, borders, text and icons from raylib, with scissor rectangles for scrolling lists. Text uses the TrueType families from `data/fonts/` (Text, below); colours and panel art come from the theme (Theme, below).
- Look sensitivities and the gyro toggle from the settings are applied in the input layer, not in the simulation, so the simulation only ever reads its input. Settings has five tabs: Display, Audio (0068), Controls (sensitivities), Accessibility (0074, below) and Bindings (the effective bindings, read only). Pause acts as Back while a screen is open, and Back first closes an open tooltip. Tabs are not focus targets, the bumpers switch them, except the recipe browser's category row (below).
- Audio (0068): the Audio tab has three sliders from 0 to 100 percent in steps of 5, Master volume (default 80), Effects volume (100: footsteps, digging, placing, menu clicks, the launch, the landing, the discovery chime) and Ambience volume (70: the biome ambience, the rain and the machine hum). They apply at once and are saved as `settings.master_volume`, `settings.effects_volume` and `settings.ambience_volume` (0 to 1). The UI records a move click when the focus moves from one widget to another (a step or the pointer, not the fallback when a screen opens), a confirm click on an activation and a back click on Back over a screen other than the title, as `Ui_State.sound_events`; the frame loop plays and empties them.
- Accessibility (0074): the Accessibility tab has nine rows, applied at once and saved with the other settings. Text size (`settings.text_scale`, 0.8 to 1.6 in steps of 0.1, default 1) multiplies every text size the UI measures and draws, on top of the interface scale (`ui_text_width_in_weight` measures at the scaled size, `ui_end` hands the scaled size to the draw layer); the layout keeps its sizes, so at large text a single line label ends in its ellipsis sooner, text fills more of its row's padding and the lines of wrapped text sit closer. Marker colours (`settings.palette`, `default` or `colour_blind`) picks the palette of the theme (Theme, below) for the bottleneck markers and the map's markers and legend: colour blind is blue, orange, black and white, then the rest of the Okabe and Ito set, told apart with deuteranopia and protanopia and by lightness; under it every machine dot on the map takes the palette's machine colour instead of its category's. Reduced motion (`settings.reduced_motion`, default off) turns the head bob off, the sprint view widening to 0 and the weather's rain and snow, sway and cloud shadows off (the weather look reads it as the Weather toggle off; the sky still greys and the rain is still heard), holds the torch flames and the block light's flicker still, holds the focus outline at its thickest and shows Mission Control's lines whole at once (their hold and fade keep their length). The Head bob, Sprint view widening and Weather rows keep their own values, so turning reduced motion off restores them. Sneak and Sprint (`settings.sneak_hold` and `settings.sprint_hold`, `hold` or `toggle`, defaults hold and toggle) choose whether the action lasts while its button is held or switches on a press (`input.md`). Touch controls (`settings.touch_overlay`, `auto`, `on` or `off`, default `auto`, 0115) shows the touch overlay in the world; `auto` is on for the Android build and off elsewhere, and `--touch-overlay` forces it on for a run (`input.md`, Touch overlay). Touch aiming (`settings.touch_interaction`, `tap` or `crosshair`, default `tap`, 0118) chooses whether a finger on the world mines, places and interacts where it touches or the crosshair scheme of 0115 applies (`input.md`, Touch overlay). Touch layout (0121) steps the selected touch layout through Default and the user's layouts and saves the choice in the user's `touch_overlay.sjson` at once, not in the settings; Edit touch layout opens the touch layout editor on the selected layout (below).
- Touch layout editor (0121, `src/ui_touch_layout_editor.odin`, `input.md` Touch overlay): a dimmed backdrop with the layout being edited drawn full size at the overlay's real scale and opacity, each button and the stick a focusable widget with a handle at its top left corner, the selected one outlined in the accent (a floating stick in the middle of its half, where it cannot move; the look is not shown). A panel in the middle holds the heading with the layout's name, the selected element's name and four rows (a button: Size and Opacity steppers, Control, a choice that steps the control, and Double tap latches, a toggle; the stick: Radius and Opacity steppers and Fixed in place, a toggle), the Name field (the on-screen keyboard) with Save as beside it, Save, Delete and Reset to Default in one row, and Close. A stepper (`ui_stepper`, shared with the texture editor's seed) shows "<  value  >": left and right step it while focused, a click on its left or right half steps down or up. Pointer: a click or tap selects an element and a drag moves it; the pointer over the panel reaches no element under it. Gamepad: the left stick moves the focus among the elements and the panel's widgets alike (one focus scope over the whole screen), Confirm selects the focused element, the d-pad (or the arrow keys) moves the selected element by 10 reference pixels while it holds the focus (the element's widget takes `Adjusts_Horizontally` and `Adjusts_Vertically` then), and L1 and R1 (Q and E) resize the selected element wherever the focus is. B or Close leaves; an unsaved draft is dropped. Save on Default and Delete on Default toast that Default cannot change, and Save and Save as toast and refuse a layout without a Start button. Save, Save as, Delete and Reset take effect between frames. The screen pauses like the settings under it.

- The recipe browser has a selection mode: opened from an assembler's panel it lists only the recipes that machine can make, and confirming one sets it on the machine and returns to the panel, which stays open underneath. The technology screen follows the browser's shape: a name sorted list with a letter wheel, a detail panel with status, cost, description, prerequisites and unlocks, Confirm queues research.

- Inventory tab strip (0094): the inventory, the recipe browser and the technology screen are three tabs of one strip (Inventory, Recipes, Research), drawn at the top of all three (`inventory_tabs`). L1 and R1 step between them from any of the three, wrapping, and a click picks one; a step replaces the top screen (`replace_top_screen`), so Back from any tab returns to what was under the strip: the world, or a lab's panel that opened the technology screen. Open_Inventory (E) closes any of the three, and on the keyboard its press is not also a tab step. The recipe browser opened as a picker from an assembler's panel shows no strip. The recipe categories are a focusable row under the strip (`ui_tabs` with `.Focus`): up from the list reaches it, left and right change the category while it holds the focus, the bumpers do not touch it, a click picks a category, and a change drops the tag filter. The pause menu reaches neither the recipe browser nor the technology screen: it lists Resume, Journal, Power, Statistics, Save, Settings, Developer (in developer mode), Quit to title and Quit.

- The statistics screen (0028) has a Production tab (window of 1, 10 or 60 minutes, items sorted by produced per minute with consumed beside it, a detail row with the machines making and using the focused item and the voided total) and a Power tab that reuses the power overview. The bottleneck overlay draws a marker above every machine: green working, yellow output full, red starved of input, fuel or power, grey idle (under the colour blind palette blue, orange, white and black); markers keep a roughly constant screen size beyond fifteen blocks.

- The map screen (0038, View or M) draws the explored area top down as one 256 by 256 image at 1 to 16 blocks per pixel, coloured by the surface block tinted half way to its biome's map colour (0058, `map_color` in `data/biomes.sjson`), with the player, machines and the prospecting layers: assayed vein footprints, magnetometer readings, core sample columns and seismic circles. The legend lists the marker colours of the palette setting (0074), then the biomes on the explored pixels of the image with their colours, the player's biome in the accent colour and marked "you are here"; when the height does not hold both lists (large UI scales) the biomes take a second column. The biome of each pixel is sampled from the generator only when the frame moves or zooms, and a pan keeps the pixels it already had. Bumpers or the right stick zoom, the left stick or pointer drag pans. The magnetometer shows a dial with a needle and strength on the HUD while selected.

- The launch pad panel (0040) has part slots, a cargo section, an Assemble button and a Launch button; Interact on the pad launches when the rocket is ready and Sneak plus Interact opens the panel. The statistics screen has a Shipments tab listing launches newest first with their cargo.

- The launch pad panel (0041) has Rocket, Contracts and Catalogue tabs switched with the bumpers or a click. Contracts shows the venture credit and the open contracts oldest first, each with its deliveries per request, time left or Late, late share and reward. Catalogue is one button per entry with its price; an order the credit does not cover (counting orders not served yet) is refused with a toast. The journal has a tab after the chapters, Contracts, with the credit, the fulfilled and late tally and the open contracts above the message log. The technology screen shows "Level n" in place of a status for an infinite technology, the next level's cost, and the effect per level where unlocks would be.

- Developer mode (0043, the Developer mode toggle on the settings screen or `--dev`): the pause menu gets a Developer entry opening a screen of buttons and toggles, all reachable with focus navigation and the pointer: fly mode, no clip (0112: flying passes through blocks, otherwise flight collides) and cheat speed toggles (queued, 0044: three times the movement speed and hand mining in a tenth of the time; 0087: a walk steps up one block ledges without jumping and a jump reaches about 2.2 blocks, while the walk cycle, the head bob and the footsteps count the walked distance divided by three and the chop and the mining hits keep their normal period and cap, so nothing sounds or looks faster), a diagnostics page choice that steps like F3 and statistics overlay and bottleneck overlay toggles (at once), one numbered button per chapter to give that chapter's kit and one to complete the quests before it, a Finish active quest button (0098) that completes the active quest with its rewards and activates the next, dawn, noon, dusk and midnight, unlock every recipe and technology, teleport to the landing pad, and a Screenshot button (0053) writing a PNG under `$XDG_STATE_HOME/mine-oh-belowed/screenshots/` with a toast naming it, and a data row (0054) with the watcher's status and a Reload data button; F8 does the same in developer mode, and every reload or failure shows a toast. The toggles for the overlays act at once; everything else is queued for the simulation and applies when the game resumes, with a toast saying so. The Settings screen's Display tab has an autosave slider from Off to 60 minutes and the Developer mode toggle.
- Texture editor (0100, `src/ui_texture_editor.odin`), the first of the editors (`DESIGN.md`, Editors): the Developer screen's last row has a Texture editor button, which opens the Textures screen and has the frame loop read `data/textures/procedural.sjson` and the edits file again first. The panel sits against the left of the safe area without a backdrop, so the world shows to its right; aim at an outcrop right of the crosshair before opening it. Left: one row per procedural texture by block name, the selected one marked with an accent bar and accent text; Confirm or a click selects. Under the list, Reset (the data file's entry for the selected texture), Save and Back, one above the other. Right, above: one image, the selected tile enlarged 6 times beside a field of 6 by 6 tiles, each cell turned, mirrored, slid and brightened as the chunk shader does a top face at that cell (`texture_field_source` through `varied_tile_texcoord`), at 3 screen pixels per texel where the column allows (up to 45 percent of its height). Right, below: the seed row (Reroll on the left, a new seed from a hash of the simulation tick and the old seed; then the seed between arrows, left and right step it by one, wrapping, and a click on its left or right half steps down or up), then one slider per parameter with the range and step of `ore_texture_parameter_ranges`; the seed row and the sliders scroll where the column is short. Focus: right from a list row goes into the controls beside it (Reroll from the upper rows), left from Reroll back to the list, down runs through the sliders; on a slider or the seed, left and right change the value, so up and down move between rows, and B returns; right from Reset, Save or Back goes to the slider in their row, up from Reset to the list. Every change regenerates the tile on the CPU and repaints the preview; while the screen is open the frame loop copies every texture's tile into the block atlas each frame (`update_atlas_block_tile`, `UpdateTextureRec` on the three face groups' tiles), so the world behind the panel shows the change in the next frame and a data reload's rebuilt atlas takes the edits back. Save writes every texture's current parameters to `$XDG_STATE_HOME/mine-oh-belowed/texture_edits.sjson` (`doc/content.md`), logs one `texture: {block = ...}` line per texture and toasts the path; unsaved edits last until the game exits, and a reload of the files keeps the entries changed since the last save. `tools/moc query textures` answers the current parameters (`doc/commands.md`). The screen pauses like the Developer screen under it.
- Window (0080): the Display tab starts with Window mode (Windowed, Borderless, Fullscreen; Borderless is the default), Resolution (Native, then 1280 by 720 up to 3840 by 2160 filtered to the monitor's size, since raylib lists no video modes), a Vsync toggle and a Frame rate cap choice (Off, 30, 40, 60, 90, 120, 144, 165, 240). Four camera sliders follow (0073), applied at once: Field of view (`settings.field_of_view`, 60 to 110 degrees vertical, default 70), Sprint view widening (`settings.sprint_field_of_view_kick`, 0 to 15 degrees added while sprinting and moving, default 6, eased in and out over 0.3 seconds of frame time; 0 turns it off, and 0074 folds it into reduced motion), Third person distance (`settings.third_person_distance`, 2 to 8 blocks behind the eye in steps of 0.5, default 4) and Third person shoulder (`settings.third_person_shoulder`, -1 to 1 blocks to the camera's right in steps of 0.1, default 0.6 so the player stands left of centre; the offset follows the yaw only, and a wall between the eye and the camera still pulls it in). A Weather toggle follows (0063, `settings.weather`, default on): off keeps the weather clear, with no rain, snow, swaying plants or cloud shadows, for less motion; 0074 folds it into reduced motion. The Sun shadows toggle of 0072 was removed by 0097; a configuration that still sets `settings.shadows` loads, and the key is ignored with one log line. A Head bob toggle comes next (0066, `settings.head_bob`, default on): on, the first person eye rises and falls 0.03 blocks with each step (0.05 sprinting), off keeps it level; 0074 folds it into reduced motion too. They apply at once and are saved with the other settings; `settings.window_mode`, `settings.resolution` (`[width, height]`, `[0, 0]` for the monitor's size), `settings.vsync` and `settings.frame_rate_cap` in the configuration take them, and a configured resolution or cap outside the lists is kept and shown as its numbers. The resolution is the window's size in Windowed and the video mode in Fullscreen; Borderless covers the monitor at its current mode, so the row is dimmed there and shows the monitor's size. The monitor's size is read once at start while the window is still windowed. Under XWayland on a desktop scaled screen (0084; since 0085 only when GLFW took X11 while `WAYLAND_DISPLAY` is set) the monitor's size is the scaled one, so Borderless shows it as, for example, "1694 x 1129 (desktop scaled)" and the row's tooltip names the ways to the panel's full size: a native Wayland window or gamescope (`doc/build.md`). A native Wayland window (0085) reaches the panel, so the row lists the choices up to the monitor's size as on X11; the fixed list stays, since raylib lists no video modes. In Steam Game Mode gamescope presents the window full screen whatever the mode, and a windowed resolution becomes the size gamescope scales up. `display.odin` holds the transition table between the modes.

## Widgets

Label, button, toggle, slider, tabs, vertical list with letter jump, grid of slots, item slot (icon, count, highlight), progress bar, tooltip panel, radial menu, text field (opens the on-screen keyboard), glyph bar, toast.

## Item slots on a gamepad

A picks up the focused stack, A on another slot drops it or swaps, L2 splits the stack in half, X sorts the active grid (Touch button row, below), the focused or hovered stack's info shows by itself after 0.4 seconds (0094, Tooltips above), R2 (Q on the keyboard, or Left Control with a click) quick moves the focused stack to the other side of a machine panel with the rules inserters follow, fuel to the fuel slot and ore to the input, and a second press within half a second or a hold moves every stack of that item (0078); in the inventory screen the same quick move sends the focused stack from the backpack to the hotbar or from the hotbar to the backpack, partial stacks of the item first, then empty slots, and what does not fit stays (0090); machine panels have Take all, Store all and Fill buttons under their slots, holding A with a stack in hand while moving the focus across machine slots distributes it evenly over the visited slots on release (the Even Distribution gesture from `input.md`). The pointer drags instead (Item slots with a pointer, below). A held stack follows the focus and the pointer, and goes back to its slot when the screen closes. Machine input slots accept only what the machine can use, and a rejected drop stays in hand. An inserter panel has an "In hand" slot for the item its arm carries: A or a drag lifts it, R2 quick moves it into the inventory, and it takes nothing in (0079).

In the inventory screen the right stick click (X on the keyboard, action `Menu_Drop`) drops: there is no Drop button (0090), and the glyph bar shows Drop on a focused or held stack. The cursor's stack, or the focused stack with nothing held, goes onto the ground in front of the player as a loose item (0062, `logistics.md`). Walking near loose items picks them up as far as they fit; where they go (tools and machines to the hotbar, the rest to the main grid) is in `logistics.md`, Loose items. In the world, `Drop_Stack` (d-pad down, X, or a long press on the selected hotbar slot of the touch overlay, 0119) drops the selected hotbar slot's stack the same way.

## Pointer

Work item 0132. The mouse, the right trackpad's pointer with its pad click, and a finger activate a widget by a tap: the press names the widget under the pointer (`Pointer_Press` in `ui_core.odin`, named in `ui_interact`), and the widget activates when the pointer lifts over that same widget without having moved more than `UI_SLOT_DRAG_SLOP` (16 UI units) from the press (`pointer_tapped`). A press released off the widget, or one that moved past the slop, even out and back, activates nothing. Confirm sounds on the release. The gamepad's Confirm on the focused widget is unchanged. A stepper steps on the tap, by the half tapped. A slider decides a press on its track by the first movement past the slop (`slider_pointer_value`): more along the track than across is the slider's drag, whose value follows the pointer from then on, only on frames where it moved, never a still pointer; more across is the scroll drag of the list it sits in, and the value stays; a release within the slop is a tap, which sets the value at the press point. The UI scale and the text scale sliders (`ui_layout_slider`) change the layout, so during their drag the value shown follows the finger while the setting changes only on the release, and the track stays under the finger; steps and taps apply at once. Exceptions that act on the press: the tab strips select on the press; the touch layout editor selects and grabs an element on the press, so the drag moves it; item slots keep their drag (Item slots with a pointer); Left Control with a click quick moves at once.

A press inside a scroll region or a list (`scroll_region_end`, `ui_list`, `scroll_list_end`: the recipes, the technologies, the statistics, the journal, power, the launch pad, the title's saves) that moves past the slop scrolls it by the pointer's movement (`pointer_drag_scroll`), including the movement up to the slop, and cancels the pending tap; not a press on an item slot, whose drag moves the stack, nor a drag along a slider's track or one an editor element holds. The focus does not follow the pointer while it scrolls, and after the drag the focused widget stays where the drag put it, even out of view, until the focus moves again, a d-pad or stick step is taken (also on a slider or a stepper, which keep the focus) or a screen requests a focus (`focus_scrolled_away`); the right stick and the wheel scroll as before. The stored pointer position is in UI units, so a UI scale change rescales it (`rescale_pointer`), keeping a still pointer's unit position true. A toggle's knob slides only from where it was drawn the frame before (`Knob_Position`); a toggle not drawn last frame, its screen just opened, starts at its value, so a value changed while the screen was closed does not slide into place as if the entry had flipped it.

## Item slots with a pointer

Work item 0124. The mouse, the right trackpad and a finger move stacks by drag and drop in every slot grid (the inventory, the machine panels, chests; a drag drops onto a filter or hand slot, a drag out of one lifts nothing), through the shared slot code (`Slot_Drag` in `ui_core.odin`, `ui_item_slot`, `finish_slot_drag` in `ui_inventory.odin`); a click on a slot activates nothing by itself. A press on a stack that then moves more than `UI_SLOT_DRAG_SLOP` (16 UI units) picks the stack up; releasing over a slot drops, merges or swaps there (`apply_slot_primary`, a machine slot's filter applies), and whatever is still held after the release goes back to where the dragged stack came from (`return_held_stack`), so a drag onto another item swaps the two slots and a release off the slots returns the stack; a leftover that fits nowhere stays on the cursor and drags at the next press. A drag whose pick up lifts nothing (a filter slot, a slot a machine emptied meanwhile) ends at once. Confirm sounds on the pick up and on the drop, not on a tap. Left Control with a click quick moves the pressed slot and starts no drag. A press and release without moving is a tap: it focuses the slot. A press resting `TOUCH_HOLD_SECONDS` (0.25 seconds, the touch overlay's long press) on a stack of two or more splits it and drags the half. The pick up and the split reach the screens as Confirm and `Menu_Secondary` on the pressed slot, so every slot screen applies them as the gamepad's. With a stack already held (A picked it up), a press drags that stack at once. The Even Distribution gesture stays with the gamepad. With the `Touch` pointer source (on Android, and while the touch overlay is on, so `--touch-overlay` tests it on the desktop) the dragged stack draws one slot height above the pointer, so the finger does not cover it; the mouse and the trackpad keep it under the pointer. A tap off the screen's content (outside its panels but the glyph bar's, its widgets, and the bottom strip of the glyph bar and the HUD's hotbar) with nothing held closes the top screen as Back does, on the panels over the running world (the inventory tabs, a machine panel, the journal, power, statistics and the map); the pause menu, the settings, the editors and the title screens stay, as does an open keyboard.

## Touch button row

Work item 0125. On Android and while the touch overlay is on (`Ui_Input.pointer_is_touch`), the inventory screen and the machine panels show a row of buttons without glyphs in the glyph bar's place (`slot_button_row`, `ui_button_bar`): Sort, Split, Transfer all, Transfer all of type. The row sits right of the HUD's hotbar, which draws under open screens, when that leaves room for four slot widths (`slot_button_strip`), else along the whole safe area as the glyph bar does (large UI scales, where it crosses the hotbar); buttons that do not fit get narrower, the widest first, their labels cut short with an ellipsis (`fit_button_widths`). The keyboard and the gamepad keep the glyph bar. The machine panels' Take all, Store all and Fill stay.

The active grid is the grid of the slot that last held the focus (`Active_Slot`): the hotbar row, the main grid, or the machine's slots. It stays while the focus is on a button or another widget off the slots, and is forgotten with the focus when the screens close. Sort (the button, or X) sorts the active grid alone: the main grid, or a chest's slots; the hotbar keeps its order, so with the hotbar active it sorts the player's main grid (`sort_target_grid`; the screens open with the focus on the hotbar), while Split and the transfers keep the hotbar as the active grid. Split takes the larger half of the active slot's stack onto the cursor, as L2 (half rounded up, so a single item is lifted whole). Transfer all moves every stack of the active grid, Transfer all of type the stacks of the active slot's item, into the grid the screen pairs it with (`transfer_target_grid`): in the inventory screen the hotbar into the main grid and the main grid into the hotbar; in a machine panel the hotbar and the main grid into the machine, the way the quick move stores (fuel to the fuel slot, ore to the input, insertion limits), and the machine into the main grid, never the hotbar. What does not fit stays where it was.

## HUD

Hotbar of eight slots bottom centre with the selected slot enlarged, the held item name above it, the name and state of the targeted block or entity near the crosshair, the current quest objective top right, toasts top left (below Mission Control's panel while it shows), a discovery card top centre, the glyph bar bottom right, the brownout warning top centre. There is no compass strip yet.

The player's hands (0066): in first person the right arm reaches in from the lower right of the view with the selected hotbar stack at the hand: an item that places a cube shaped block as a cube of 0.35 blocks with the block's top, side and bottom atlas tiles, shaded per face and lit like the arm, turning with it (0092); any other item (a torch, a slab, stairs and ground cover included) as its icon, a small cube in its colour for an item without an icon, nothing for an empty slot; it chops while mining and swings once when a machine or block is placed, and it draws over the world, so a wall in front never hides it. In third person the whole body walks, sprints, chops and places, and the head follows the look.

Mission Control on screen (0069): quest notices are sorted by key. Mission Control's own lines (keys starting `mc_`) go to a panel at the top left, the toasts moving below it while it shows: the panel colour with an accent border down the left, the venture's mark (a stepped chevron drawn from fills, no image) and "MISSION CONTROL", then the line typing itself out at 40 characters a second with a blinking cursor, held 4 seconds once typed and faded over half a second. Lines that arrive meanwhile wait and follow one another (at most eight; the oldest waiting one gives way). A short rising chime plays as each line starts (`mission_control_chime`). No button acts on a line, since in the world Confirm is also Jump and Mine; a line runs on its own timing and the journal keeps it. The panel draws only with no screen open, its time runs on underneath one. A discovery (`item_discovered`, 0052) shows a card centred at the top (below the touch overlay's Back and Start while the overlay is drawn, 0123) instead of a toast for 3 seconds: the item's icon, "Discovered" dim and the item's name, with the discovery chime; a second discovery replaces the card. Everything else (finished research, the capsule landing, the venture's contract and trade notes) stays a toast. The journal's message log frames Mission Control's rows the same way (accent border and mark, the row a gap taller), other rows stay plain. The map draws a parachute over the landing pad while a capsule descends (0067), and after an orbital survey a satellite crosses the map from west to east along the pad's row over 6 seconds, over the pad halfway; in the world a small bright quad crosses the sky the same 6 seconds, from the western horizon over the top to the eastern one along the sun's path. The descent and the pass are render state kept with the particles, never read by the simulation, and a loaded world starts neither.

The biome banner (0058): when the biome under the player has changed and stayed changed for 2 seconds, its name fades in at top centre on the line below the brownout warning, shows for 3 seconds in all and fades out; the first biome of a world is announced the same way. A short visit into another biome and back announces nothing. The banner pauses while a screen is open.

A small bar above the crosshair fills while a block is being dug (2026-09-27), and in the touch overlay's tap scheme (0118), which draws no crosshair, a ring around the mined block fills clockwise instead (`draw_mining_ring`, placed through the camera the world was drawn with); a block being placed has no preview cube, the target outline says where it goes (it outlines the targeted block's shape, a slab's half or the half block wide box a torch is aimed at, 0061); a slab goes into the upper half of its cell when placed against the underside of a block or high up on a side face, else into the lower half, and stairs rise away from the player, a quarter turn further per Rotate while they are held. The ray stops at ground cover (0082: tufts, flowers, reeds), whose bounds fill its cell; a block placed at cover takes the cover's cell and replaces it, and a machine, belt or pipe aimed at cover stands on the ground under it and clears the cover in its footprint, and a belt drag lays over cover. Mining the block under cover drops the cover as a loose item. A machine ghost is the machine's own model, tinted translucent green or red at full brightness with its part at rest, and turns with Rotate (0081); a machine without a model keeps the translucent box. A belt ghost is the belt shape's own surface with a white chevron along the flow (following a ramp's slope), an inserter ghost outlines its pickup cell dim and its drop cell bright at the machine's reach with a chevron over the post, and drills, splitters, fluid machines and poles draw their arrows, ports and volumes over the model. Under the crosshair (0052) up to three lines stack with no gaps: the targeted block's name in dim text, or an entity's name and state; the pickaxe the block needs (0051); the vein line. Nothing shows when the ray hits nothing. A discoverable ore block reads "Unknown ore" until its drop item was obtained once, and the vein line replaces the vein type's name with "Unknown ore" (size and units left stay) until one of its discoverable ores is obtained; a vein type with no discoverable output (a quarry, the deep bauxite vein) is always named.

## Text

Text is drawn with TrueType fonts (0077) rasterised at `round(text_size * pixels_per_unit)` pixels for each size in use and drawn at whole pixel positions, so stems are even at every UI scale (raylib's 10 pixel bitmap font scaled up gave one and two pixel stems, couch test 1). Headings and the HUD quest title use the bold weight. The families live in `data/fonts/<id>/` with their licences and are listed in `data/fonts/fonts.sjson`: technical faces first (Exo 2 the default, Titillium Web, Rajdhani, Oxanium, Chakra Petch, Jura, Electrolize, Play, Quantico, Orbitron, Michroma), then plain faces for comparison, then the monospace families for the diagnostics overlay. The Display tab has a Font choice and a Diagnostics font choice, applied at once and saved; `settings.font` and `settings.monospace_font` in the configuration take the ids. Font files are presentation data for hot reload.

## Theme

The UI's colours and art metrics come from `data/ui/theme.sjson` (0071, `src/ui_theme.odin`): colours as `[red, green, blue, alpha]` for `panel`, `panel_edge`, `panel_highlight`, `widget`, `widget_hover`, `widget_active`, `accent`, `text`, `text_dim`, `focus`, `divider`, `tooltip`, `toast`, `danger` and the map's `map_marker_raw`, `map_marker_intermediate`, `map_marker_tool`, `map_marker_machine` and `map_marker_block`, and the lengths `border` (edge, highlight and divider lines), `corner` (the cut panel corners) and `focus_pulse` (how much the focus outline thickens at the top of its pulse), in UI units, and the marker palettes (0074): `palettes = {default = {...} colour_blind = {...}}`, each with `working`, `waiting`, `missing` and `idle` (the bottleneck states) and `map_player`, `map_machine`, `map_assayed`, `map_magnetometer`, `map_core_sample`, `map_core_sample_vein`, `map_seismic` and `map_resolved` (the map's markers and legend). Each palette keeps its four states apart and its eight map colours apart (`test_palettes_colour_every_marker_apart`). A key left out keeps its default, and the defaults are the look from before the file, so the art below only shows where the file sets it; an unknown key, a wrong type or a value out of range refuses the file with its name (at start the game exits, on a reload it keeps the old theme). A colour with alpha 0 turns its element off. The theme lives in `Ui_State.theme` (the defaults until one is set); the screens that still name `UI_TEXT_COLOR`, `UI_PANEL_COLOR` and the other colour names, and `UI_BORDER`, read package variables that `apply_ui_theme` sets from the same theme. The layout sizes (`UI_ROW_HEIGHT`, `UI_SLOT_SIZE`, `UI_PADDING`, `UI_GAP`, the text sizes) and the font roles are not in the file yet: the screens use the sizes in compile time constants, and the fonts follow the Display tab (Text, above). The file and the icons are presentation data for hot reload.

Art, drawn with fills and outlines only, no images:

- A panel is a fill, an edge line in `panel_edge` and a highlight line in `panel_highlight` one border inside it, with the corners cut by `corner` as square notches: the fill is three rectangles and each line twelve straight pieces, none overlapping, since the colours may be translucent. With `corner` 0 and no highlight it is the old fill and outline. Tooltips are drawn the same way in `tooltip` with the accent as their edge; toasts are a plain `toast` fill.
- Buttons, rows, slots and tabs are `widget`, `widget_hover` under the pointer and `widget_active` while Confirm is held on the focused one or the pointer is held on the hovered one.
- The focus outline is `focus` (the accent), 4 units plus `focus_pulse` times a cosine pulse of 1.4 seconds, growing inwards so it never leaves the widget; the UI audit runs the pulse at both ends.
- Tabs draw their icon before the label when the screen gives one (the recipe browser's categories, the inventory tab strip), the selected tab's label in the accent over a 4 unit accent underline, and a `divider` line along the strip.
- Sliders fill their track in the accent. A toggle is a switch: a track filled in the accent while on, and a knob that slides to the value's side over an eighth of a second.

The UI icons are `data/ui/icons/<name>.png`, 16 by 16 RGBA, one per `Ui_Icon`: the pad's `button_south`, `button_east`, `button_west`, `button_north`, `bumper_left`, `bumper_right`, `trigger_left`, `trigger_right`, `stick_left`, `stick_right`, `dpad`, `menu`, `view`; `key`, a blank key cap; the bumpers read L1 and R1, the triggers LT and RT and the sticks L and R (0095); the item categories `category_raw`, `category_intermediate`, `category_tool`, `category_machine`, `category_block` and the recipe categories without one, `category_logistics`, `category_power`, `category_science`; `mission_control`, `journal`, `map`, `settings`, `search`; and the inventory tabs `inventory`, `recipes`, `technologies`. They are packed into a UI atlas by the item atlas code and drawn with the `Ui_Icon` draw command. The glyph bar draws the pad button's icon on the gamepad (`glyph_icon`), and on the keyboard the key's name from the strings on the `key` cap. Under the default palette the map's machine dots take the marker colour of their machine item's category (a machine without an item, the drop capsule, the machine marker); every shipped machine item is in the machine category, so the dots share one colour until other categories place entities. The shipped icons are placeholders from `tools/make_placeholder_textures.py`.

## Icons

An item's icon is its tile in the item atlas, read from `data/textures/items/<item id>.png` (16 by 16 RGBA with transparency, 0060), and draws in slots, the hotbar, the recipe browser and every other icon place through `draw_item_icon`. An item without a file falls back to its placed block's atlas tile, and an item that places no block to a coloured square with two letters. On belts and on the ground an item with an icon is a camera facing quad of its tile, 0.4 blocks, and one without is a small cube in its category's colour. The shipped icons are placeholders from `tools/make_placeholder_textures.py` (see `doc/content.md`, Textures); hand made art only replaces the files.

## On-screen keyboard

A QWERTY grid under the text field, driven by focus navigation and the pointer, with shift, space, backspace and done as large keys. While typing, A types the focused key, X is backspace, Y is shift (a caps lock style toggle) and B is done, so the common keys are one press away; the panel shows only the edited field and the keys. A physical keyboard types into the same field when present, and Enter or Escape finishes. Names are capped at 32 characters, seeds at 20 digits, ASCII only (0024). The title screen is a plain sky coloured backdrop with the name and version, since a world view would need a session.
